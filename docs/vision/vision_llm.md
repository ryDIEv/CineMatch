# CineMatch — Vision модуля ИИ-агентов

> Подробная документация модуля — [`documents/agents/`](../../documents/agents/README.md).

## 1. Общее описание

Модуль ведёт диалог с пользователем и принимает все решения: что спросить, какие фильмы искать, как понять ответ, что сохранить. Он состоит из оркестратора (обычный код), классификатора намерений и трёх агентов, в которых модель сама выбирает действия и вызывает инструменты модуля данных.

| Компонент | Роль |
|---|---|
| Оркестратор | Принимает сообщение, определяет этап диалога, передаёт нужному агенту, хранит состояние сессии |
| Классификатор намерений | Понимает, чего хочет пользователь: подобрать фильм, отметить просмотр, изменить город, удалить данные, или сообщение не по теме |
| Агент-распознаватель состояния | Расспрашивает о настроении, времени, компании, учитывает погоду и историю оценок |
| Агент-рекомендатель | Выбирает критерии поиска, получает фильмы из каталога, объясняет выбор, понимает реакцию на подборку |
| Агент-компаньон | Узнаёт оценку после просмотра и принимает отметки «посмотрел X» |

## 2. Ключевые возможности

1. Диалог в свободной форме — без меню и обязательных кнопок.
2. Подборка из трёх реальных фильмов с объяснением для каждого.
3. Понимание реакции: выбор, другие варианты, отказ, сообщение не по теме.
4. Оценка выбранного фильма при следующем визите и отметка просмотренного своими словами.
5. Трасса решений: какие инструменты и с какими параметрами вызывал агент.
6. Ограничение темы и защита от попыток изменить поведение ассистента.

## 3. Требования

**Функциональные:** вход через `handle_user_turn(user_id, message)`; согласие и выбор города перед началом работы; 1–2 уточняющих вопроса; поиск фильмов только через инструмент `find_movies`; три фильма с обоснованием; распознавание реакции (`select`, `another`, `stop`, `off_topic`); оценка по шкале 1–10; удаление данных по команде.

**Нефункциональные:** ответ на сообщение — до 8 секунд; невалидный ответ модели никогда не показывается пользователю; агент может вызывать только свои инструменты; модель меняется в конфигурации без изменения кода; каждое действие агента записывается в журнал.

## 4. Взаимодействие

- **С интерфейсом:** одна функция `handle_user_turn`; ответ — структура `AgentResponse` (текст, фильмы, трасса решений, этап диалога).
- **С модулем данных:** инструменты для моделей (`find_movies`, `get_user_profile` и др.) и служебные функции для оркестратора (сессии, настройки, выбор).
- **С LLM:** OpenRouter по API, совместимому с OpenAI, с поддержкой вызова инструментов.

## 5. Процессы

Основной цикл: сообщение → классификация намерения → агент текущего этапа → вызовы модели и инструментов → проверка ответа по схеме → сохранение сессии → ответ интерфейсу. Диаграммы — в [146 Logic Scheme](../../documents/agents/146.logic-scheme.md) и [155 Sequence-диаграммы](../../documents/agents/155.sequence-diagrams.md).

## Будущий функционал

Агент-планировщик (напоминания, подписки, подборка новинок); режим локальной модели; оценка уверенности распознавателя вместо фиксированного числа уточняющих вопросов.
