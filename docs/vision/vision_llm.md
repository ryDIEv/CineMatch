# CineMatch — Vision модуля ИИ-агентов

> Подробная документация модуля — [`documents/agents/`](../../documents/agents/README.md). Обоснование архитектуры — [`documents/rationale.md`](../../documents/rationale.md).

## 1. Общее описание

Модуль ведёт диалог с пользователем. Код отвечает за то, что нельзя доверить модели: согласие, выбор города, удаление данных, лимиты и проверку ответа. Внутри разговора решения принимает агент: что спросить, какие инструменты вызвать, какие фильмы предложить, как понять ответ пользователя.

| Компонент | Роль |
|---|---|
| Оркестратор (код) | Принимает сообщение, проверяет согласие и город, подтверждает удаление данных, следит за лимитами, проверяет ответ агента, хранит сессию |
| Классификатор запросов | Относит сообщение к одному из классов: о кино, удаление данных, не по теме, небезопасное. Агент вызывается только для сообщений о кино |
| Агент CineMatch | Ведёт подбор: извлекает контекст вечера (инструмент `extract_context`), задаёт недостающие вопросы, учитывает погоду и оценки, ищет фильмы в каталоге, объясняет выбор, понимает реакцию, принимает оценки |

## 2. Ключевые возможности

1. Диалог в свободной форме — без меню и обязательных кнопок.
2. Подборка из трёх реальных фильмов с объяснением для каждого.
3. Понимание реакции своими словами: выбор, другие варианты, отказ.
4. Оценка выбранного фильма при следующем визите и отметка просмотренного своими словами.
5. Трасса решений: какие инструменты и с какими параметрами вызывал агент.
6. Защитные механизмы: ограничение темы, фиксированный список инструментов, проверка ответа кодом.

## 3. Требования

**Функциональные:** вход через `handle_user_turn(user_id, message, movie_id=None)`; согласие и выбор города перед началом работы; не более двух вопросов до подборки; поиск фильмов только через инструмент `find_movies`; три фильма с обоснованием; распознавание реакции агентом; оценка по шкале 1–10; удаление данных по фразе пользователя с подтверждением.

**Нефункциональные:** ответ на сообщение — до 10 секунд; не более 8 вызовов модели на сообщение; невалидный ответ модели и фильм вне каталога никогда не показываются пользователю; агент вызывает только разрешённые инструменты; модель меняется в конфигурации без изменения кода; в запросах к модели нет данных, позволяющих установить личность; каждое действие агента записывается в журнал.

## 4. Взаимодействие

- **С интерфейсом:** одна функция `handle_user_turn`; ответ — структура `AgentResponse` (текст, фильмы, трасса решений, этап диалога).
- **С модулем данных:** инструменты агента (`find_movies`, `save_rating` и др.) и служебные функции оркестратора (сессии, настройки, удаление).
- **С языковой моделью:** RouterAI по API, совместимому с OpenAI; агент построен на Pydantic AI.

## 5. Процессы

Основной цикл: сообщение → проверка инвариантов → классификатор запроса → агент (вызовы модели и инструментов) → проверка ответа → сохранение сессии → ответ интерфейсу. Диаграммы — в [146 Logic Scheme](../../documents/agents/146.logic-scheme.md) и [155 Sequence-диаграммы](../../documents/agents/155.sequence-diagrams.md).

## Будущий функционал

Агент-планировщик (напоминания, подписки, подборка новинок); режим локальной модели.
