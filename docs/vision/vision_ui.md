# CineMatch — Vision модуля интерфейса

> Подробная документация модуля — [`documents/ui/`](../../documents/ui/README.md). Прототип — [`documents/ui/prototype/index.html`](../../documents/ui/prototype/index.html).

## 1. Общее описание

Модуль интерфейса — то, что видит пользователь, и то, как приложение запускается. Он состоит из веб-приложения (чат с агентами, история оценок, настройки), API-слоя, который связывает веб-приложение с модулем агентов, и конфигурации Docker Compose. Логики подбора в модуле нет: каждое сообщение пользователя передаётся агентам, а их ответ отображается.

| Компонент | Роль |
|---|---|
| Веб-приложение | Чат, карточки фильмов, раскрываемая трасса решений агента, экраны «История и оценки» и «Мои данные» |
| API-слой | REST API и потоковые ответы (SSE) поверх `handle_user_turn` и функций модуля данных |
| Развёртывание | Docker Compose: запуск всего приложения одной командой на `localhost` |

## 2. Ключевые возможности

1. Чат без меню и обязательных кнопок: всё пишется своими словами.
2. Карточки фильмов в виде билетов с постером, возрастной маркировкой и объяснением; фильм можно выбрать нажатием на карточку.
3. Ход работы агента в реальном времени: «Смотрю ваши оценки…», «Ищу фильмы…».
4. Раскрываемый блок «Как агент выбирал».
5. Экран «История и оценки» и экран «Мои данные» (город, удаление данных).
6. Тёмная и светлая темы, адаптация под мобильный экран, доступность с клавиатуры.
7. Запуск командой `docker compose up`.

## 3. Требования

**Функциональные:** отправка сообщения и получение ответа потоком; отображение всех типов ответа агентов; выбор фильма нажатием на карточку (в чат уходит сообщение «Выбираю «…»», решение принимает агент); история оценок; изменение города; удаление данных с подтверждением; проверка ввода (пустое, слишком длинное сообщение).

**Нефункциональные:** первый признак ответа — не позже 1 секунды после отправки; интерфейс не зависает во время работы агентов; запуск с нуля одной командой; секреты только в `.env`; соответствие базовым требованиям доступности (контраст, фокус, клавиатура).

## 4. Взаимодействие

- **С модулем агентов:** `handle_user_turn(user_id, message) → AgentResponse`.
- **С модулем данных:** история оценок, настройки, удаление данных.
- **С браузером:** REST API `/api/v1/…` и поток событий SSE.

## 5. Процессы

Отправка сообщения и потоковый ответ, выбор фильма карточкой, первый визит — диаграммы в [146 Logic Scheme](../../documents/ui/146.logic-scheme.md) и [155 Sequence-диаграммы](../../documents/ui/155.sequence-diagrams.md).

## Будущий функционал

Telegram-бот на том же API; доставка напоминаний и подборки новинок; вход и несколько профилей; развёртывание на сервере; экран статистики для администратора.
