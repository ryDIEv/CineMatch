# CineMatch — Vision проекта

> Краткое описание проекта. Подробности — в vision модулей ([агенты](vision_llm.md), [данные](vision_db.md), [интерфейс](vision_ui.md)) и в [проектной документации](../../documents/README.md).

## 1. Общее описание

Выбор фильма на вечер часто занимает больше времени, чем сам фильм: каталоги огромные, фильтры приходится настраивать вручную, а выбор зависит от того, что обычные сервисы не учитывают — настроения, усталости, свободного времени, погоды за окном.

**CineMatch** — веб-приложение с ИИ-агентами, которое превращает поиск по каталогу в короткий разговор. Пользователь пишет своими словами, как прошёл день и сколько у него времени; агенты учитывают погоду и историю его оценок, предлагают три фильма с объяснением выбора и запоминают оценку после просмотра.

Цель — выбор фильма примерно за минуту.

## 2. Ключевые возможности

1. **Подбор в диалоге.** Настроение, свободное время, компания, пожелания, погода и история оценок превращаются в три фильма с постером, возрастной маркировкой и объяснением, почему они подходят.
2. **Ответ своими словами.** «Беру второй», «давай что-нибудь посмешнее», «в другой раз» — агент сам понимает, что имелось в виду. Фильм можно выбрать и нажатием на карточку.
3. **Прозрачность решений.** Под подборкой можно раскрыть, как агент выбирал: какие данные смотрел и с какими критериями искал.
4. **Оценки и история.** При следующем визите CineMatch спросит, как прошёл выбранный фильм; просмотренное без CineMatch можно отметить фразой «посмотрел X, на 8 из 10». Все оценки — на отдельном экране.
5. **Только реальные фильмы.** Модель выбирает критерии поиска, а фильмы берутся из локального каталога, загруженного из TMDB, — без выдуманных названий и фактов.
6. **Бережное отношение к данным.** Согласие перед началом работы, данные хранятся только на компьютере пользователя, удаление одной командой.
7. **Запуск одной командой.** `docker compose up` — и приложение открывается на `localhost`.

## 3. Архитектура и модули

```
Браузер ──► Веб-интерфейс (React) ──► API (FastAPI) ──► Модуль ИИ-агентов ──► OpenRouter (LLM)
                                                    └──► Модуль данных ──► SQLite, TMDB, Open-Meteo
```

| Модуль | Ответственный | Состав |
|---|---|---|
| ИИ-агенты | участник, реализующий модуль агентов | Оркестратор диалога, классификатор намерений, агенты: распознаватель состояния, рекомендатель, компаньон |
| Данные | участник, реализующий модуль данных | SQLite, загрузка каталога из TMDB, погода Open-Meteo, функции для агентов |
| Интерфейс | участник, реализующий модуль интерфейса | Веб-приложение, API-слой, развёртывание в Docker |

Агентом в проекте называется компонент, в котором языковая модель сама выбирает следующее действие и вызывает инструменты (tool use). Оркестратор и загрузка каталога — обычный код.

## 4. Объём MVP и будущий функционал

**MVP** — всё из раздела 2 для одного локального пользователя. Архитектура с самого начала рассчитана на нескольких пользователей: все данные привязаны к идентификатору пользователя.

**Будущий функционал** (после MVP, в порядке приоритета):

| Функция | Что даёт |
|---|---|
| Подборка новинок | Раз в неделю — новые фильмы, подходящие под вкус пользователя |
| Telegram-бот | Тот же диалог в мессенджере |
| Напоминания | Напоминание оценить фильм и пользовательские напоминания («в пятницу в 20:00») |
| Подписки | Уведомления о новых сериях сериалов и премьерах |
| Несколько пользователей | Вход, отдельные профили, развёртывание на сервере |
| Локальные модели | Работа без внешнего LLM API |
| Совместный выбор | Подбор фильма для компании с учётом вкусов каждого |
