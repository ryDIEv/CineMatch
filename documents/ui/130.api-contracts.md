# 130 — API Contracts

*CineMatch. Модуль интерфейса* | [оглавление модуля](README.md)

REST API backend, базовый путь `/api/v1`, формат JSON. Версия REST API — `0.1.0`, версия `AgentResponse` — `0.4.0` ([130 модуля агентов](../agents/130.api-contracts.md)). Схема OpenAPI генерируется FastAPI автоматически: `/api/docs`.

| Метод и путь | Назначение | Ответ |
|---|---|---|
| `GET /api/v1/health` | Проверка работы | `{"status": "ok", "catalog_size": 8421}` |
| `GET /api/v1/session` | Состояние при открытии | `{"consent": true, "city": "Москва", "has_pending_feedback": true}` |
| `POST /api/v1/consent` | Согласие кнопкой | `AgentResponse`; `{"accepted": false}` возвращает правила снова |
| `POST /api/v1/messages` | Сообщение агенту, ответ потоком SSE | события `progress`, `response`, `error` |
| `GET /api/v1/history?limit=50` | История оценок и выборов | `{"items": [HistoryItem]}` — схема в [130 данных §4.16](../data/130.api-contracts.md#416-get_history) |
| `GET /api/v1/cities?query=каз` | Варианты города | `{"items": [{"name": "Казань", "region": "Татарстан", "country": "Россия", "latitude": 55.79, "longitude": 49.12}]}` |
| `PUT /api/v1/settings` | Сохранить город | `{"city": "Казань", "latitude": 55.79, "longitude": 49.12}` |
| `DELETE /api/v1/me` | Удалить данные пользователя | `{"deleted_counts": {"user_ratings": 12, "user_choices": 3, "sessions": 1, "users": 1}}` |

**Открытие приложения.** API-слой вызывает `GET /api/v1/session`, затем отправляет `POST /api/v1/messages` с текстом `/start`. `/start` обрабатывается оркестратором до классификатора и модели; в историю диалога не попадает ([146 агентов §3](../agents/146.logic-scheme.md#3-служебное-сообщение-start)).

**POST /api/v1/consent**

```json
{"accepted": true}
```

Ответ — `AgentResponse` с `type="question"` и просьбой назвать город. При `accepted=false` — `type="consent"`, правила показываются снова, данные не сохраняются. Оба пути ведут в `set_consent(user_id, accepted)` ([contracts §4.2](../overall/contracts.md#42-согласие)).

**POST /api/v1/messages**

Запрос:

```json
{"text": "Выбираю «Двое и собака»", "movie_id": 205}
```

Ответ — поток `text/event-stream`. Первое событие `progress` отправляется до обращения к модели; `step` — закрытый перечень `classify`, `tool`, `check`, `text` — готовая фраза из [110 агентов §4](../agents/110.ui-ux.md#4-фразы-хода-работы).

```
event: progress
data: {"step": "classify", "text": "Определяю, что вы написали…"}

event: progress
data: {"step": "tool", "text": "Ищу фильмы…"}

event: response
data: {"contract_version": "0.4.0", "type": "confirmation", "text": "Хороший выбор на вечер…", "movies": [], "trace": [], "stage": "dialog", "error_code": null}
```

Ошибка в потоке:

```
event: error
data: {"code": "LLM_UNAVAILABLE", "message": "Сервис подбора временно недоступен. Попробуйте через минуту."}
```

Тексты ошибок — дословно из [contracts §6](../overall/contracts.md#6-ошибки); API-слой не придумывает свои формулировки.

**Ошибки HTTP**

| Код | Когда | Тело |
|---|---|---|
| 400 | Пустой текст или более 1000 символов | `{"code": "INVALID_INPUT"}` или `{"code": "INPUT_TOO_LONG"}`; `message` из contracts §6 |
| 404 | Город не найден | `{"code": "CITY_NOT_FOUND", "message": "…"}` |
| 409 | Второй ход, пока идёт первый | `{"code": "SESSION_BUSY", "message": "Дождитесь ответа на предыдущее сообщение."}` |
| 503 | Каталог не загружен (`catalog_size == 0`) | `{"code": "CATALOG_EMPTY", "message": "Каталог фильмов пуст. Запустите загрузку каталога."}` |

**Пустой каталог.** Проверка выполняется до открытия SSE: при `catalog_size == 0` API-слой отвечает `503 CATALOG_EMPTY`. Если каталог опустел во время хода, оркестратор возвращает `AgentResponse(type="error", error_code="CATALOG_EMPTY")`, API-слой передаёт его событием `error`; второй формат ответа не вводится.

**Блокировка.** API-слой не создаёт свой lock: он спрашивает у оркестратора, занят ли пользователь, и при занятом возвращает `409` до открытия потока. Оркестратор снимает блокировку в `finally`, в том числе при `TURN_TIMEOUT_S` ([146 агентов §9](../agents/146.logic-scheme.md#9-лимиты-тайм-ауты-и-блокировка)).

**Текущий пользователь.** `CurrentUser` — единственное место, где определяется `user_id`: в MVP `web:local` из `CINEMATCH_USER_ID`. Заголовка авторизации в MVP нет.

### Будущий функционал

Аутентификация (заголовок `Authorization`), эндпоинты подборки новинок и подписок, вебхук Telegram-бота, `/metrics` для отладочных интерфейсов.
