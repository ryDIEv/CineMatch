# Контракты CineMatch

*Общая часть. Единственный источник определений структур, ошибок и правил обмена между модулями.*

Документ обязателен для всех трёх модулей. Документы `130` модулей ссылаются сюда и не повторяют поля, коды и пределы. Изменение любой структуры или кода ошибки — через pull request с одобрением всех трёх ответственных и записью в [145 модуля агентов](../agents/145.architecture-decisions.md) (ADR-039).

| | |
|---|---|
| Версия контрактов | `0.3.0` (semver) |
| Версия `AgentResponse` | `0.3.0` |
| Версия REST API | `0.1.0` (см. [130 модуля интерфейса](../ui/130.api-contracts.md)) |
| Версия функций модуля данных | `0.1.0` (см. [130 модуля данных](../data/130.api-contracts.md)) |
| Код | `cinematch/overall/contracts.py`, `cinematch/overall/errors.py` — см. [build.md](build.md) |

## 1. Правила версионирования

1. Версия контракта — semver. Добавление необязательного поля — minor; удаление или переименование поля, изменение типа, смена значений перечня — major.
2. Несовместимое изменение `AgentResponse` — новый major (`1.0.0`) и новый путь REST API (`/api/v2`); старый путь живёт, пока его не удалили решением ADR.
3. Значение `contract_version` в ответе всегда равно версии структуры, которой он собран. API-слой не переписывает это поле.
4. Перечень значений (`type`, `stage`, `kind`, `step`, классы запроса) закрыт. Новое значение — изменение перечня и запись в этом документе.
5. Изменение текста ошибки для пользователя — не изменение контракта, но требует правки таблицы раздела 6 и [110](../agents/110.ui-ux.md).

## 2. Модели

Все модели — Pydantic v2 в `cinematch/overall/contracts.py`. Имена полей в JSON и в Python совпадают, `snake_case`.

### 2.1. MovieCard — карточка фильма из каталога

| Поле | Тип | Обязательно | Ограничения |
|---|---|---|---|
| `movie_id` | int | да | первичный ключ локального каталога |
| `tmdb_id` | int | да | идентификатор TMDB |
| `title` | string | да | русское название; при пустом ответе TMDB — исходное, затем «Без названия» |
| `year` | int или null | нет | год выпуска |
| `runtime` | int или null | нет | минуты |
| `rating` | float или null | нет | рейтинг TMDB 0–10 |
| `vote_count` | int | да | число голосов TMDB |
| `age_rating` | string или null | нет | `0+`, `6+`, `12+`, `16+`, `18+`; `null` — не определена |
| `genres` | string[] | да | русские названия жанров, порядок из справочника |
| `poster_url` | string или null | нет | `https://image.tmdb.org/t/p/w342/…`; `null` — постер отсутствует |

```json
{
  "movie_id": 101,
  "tmdb_id": 447332,
  "title": "Тихий дом у моря",
  "year": 2014,
  "runtime": 98,
  "rating": 7.8,
  "vote_count": 1240,
  "age_rating": "12+",
  "genres": ["Драма", "Комедия"],
  "poster_url": "https://image.tmdb.org/t/p/w342/abc.jpg"
}
```

`MovieCard` — то, что возвращает модуль данных и что показывает экран истории. Никаких полей «объяснение», «причина», «рекомендация» в карточке нет.

### 2.2. RecommendedMovie — карточка в подборке

`RecommendedMovie` = `MovieCard` + `reason`.

| Поле | Тип | Обязательно | Ограничения |
|---|---|---|---|
| все поля `MovieCard` | | да | см. 2.1 |
| `reason` | string | да | 1–2 предложения, ≤ 240 символов; ссылается на слова пользователя и поля карточки |

```json
{
  "movie_id": 101,
  "tmdb_id": 447332,
  "title": "Тихий дом у моря",
  "year": 2014,
  "runtime": 98,
  "rating": 7.8,
  "vote_count": 1240,
  "age_rating": "12+",
  "genres": ["Драма", "Комедия"],
  "poster_url": "https://image.tmdb.org/t/p/w342/abc.jpg",
  "reason": "Спокойная тёплая история, в самый раз для дождливого вечера."
}
```

`reason` формирует агент; `MovieCard` — код модуля данных. Склейка выполняется в оркестраторе: агент возвращает `movie_ids` и `reasons`, оркестратор подставляет карточки из результата `find_movies` текущего хода.

### 2.4. EveningContext — контекст вечера

Результат инструмента `extract_context`.

| Поле | Тип | Значения |
|---|---|---|
| `mood` | string или null | `calm`, `cheerful`, `sad`, `tired`, `tense`, `other` |
| `energy` | string или null | `low`, `medium`, `high` |
| `available_minutes` | int или null | 30–600 |
| `company` | string или null | `alone`, `partner`, `friends`, `family` |
| `genre_wishes` | string[] | русские названия жанров; пусто — пожеланий нет |
| `genre_avoid` | string[] | русские названия жанров; пусто — запретов нет |
| `notes` | string или null | ≤ 200 символов, свободные детали |

`null` означает «пользователь не сказал». Правила перевода контекста в параметры поиска — [120 модуля агентов](../agents/120.data-model.md#2-правила-контекст--критерии-поиска).

### 2.5. SessionState — состояние диалога

Хранится как JSON в таблице сессий; физическая модель — [120 модуля данных](../data/120.data-model.md).

| Поле | Тип | Описание |
|---|---|---|
| `stage` | string | `consent`, `onboarding`, `dialog`, `confirm_delete` |
| `pending` | object или null | `{choice_id, movie_id}` — кэш неоценённого выбора; источник истины — таблица выборов |
| `messages` | array | до 20 последних сообщений в формате истории модели; `/start` в историю не попадает |
| `context` | EveningContext или null | последний извлечённый контекст |
| `last_shown_ids` | int[] | фильмы последней подборки, до 3 |
| `shown_ids` | int[] | до 50 последних показанных фильмов; старые вытесняются |
| `clarifications_asked` | int | вопросов в текущем подборе; сбрасывается после показа подборки |

### 2.6. AgentOutput — структурированный ответ агента

| Поле | Тип | Ограничения |
|---|---|---|
| `kind` | string | `question`, `recommendations`, `feedback_question`, `confirmation`, `message` |
| `text` | string | ≤ 1200 символов, ровно один вопрос, если `kind = question` |
| `movie_ids` | int[] | 0–3; ровно 3, если `find_movies` вернул не меньше трёх |
| `reasons` | string[] | длина равна `movie_ids`; каждый ≤ 240 символов |

### 2.7. AgentTrace — шаг трассы

| Поле | Тип | Ограничения |
|---|---|---|
| `step` | string | понятный пользователю этап: «Контекст», «Погода», «Оценки», «Поиск», «Проверка» |
| `action` | string | вызов и его содержательные параметры, например `find_movies(жанры: комедия; длительность ≤ 100)` |
| `summary` | string | результат в человекочитаемой форме, например «найдено 9 фильмов» |

В трассе нет системных промптов, ключей, `user_id` и служебных путей.

### 2.8. RequestClass — класс запроса

| Значение | Этап | Что делает оркестратор |
|---|---|---|
| `cinema` | `dialog` | вызывает агента |
| `delete_data` | `dialog` | переводит сессию в `confirm_delete`, спрашивает подтверждение |
| `off_topic` | `dialog` | отказ без вызова агента |
| `unsafe` | `dialog` | отказ без вызова агента |
| `yes` | `confirm_delete`, `consent` | выполняет действие этапа |
| `no` | `confirm_delete`, `consent` | отменяет действие этапа |

Промпты классификатора — [125 модуля агентов](../agents/125.prompts.md). На этапе `dialog` применяется промпт на 4 класса, на этапах `confirm_delete` и `consent` — на 2 класса.

## 3. Сообщения о ходе работы

`handle_user_turn` принимает необязательный обработчик:

```python
async def handle_user_turn(
    user_id: str,
    message: str,
    movie_id: int | None = None,
    on_progress: Callable[[str, str], None] | None = None,
) -> AgentResponse
```

`on_progress(step, text)` — синхронный вызов без возврата; API-слой кладёт событие в очередь SSE. Обе функции оркестратора асинхронные, потому что ход ждёт модель и инструменты. События формирует оркестратор; API-слой только перекладывает их в SSE (`event: progress`) и не придумывает ни шагов, ни фраз. Ошибка в обработчике не прерывает ход (записывается в журнал).

| `step` | Когда вызывается | Пример `text` |
|---|---|---|
| `classify` | сразу при приёме сообщения, до вызова классификатора | «Определяю, что вы написали…» |
| `tool` | перед каждым вызовом инструмента | «Смотрю ваши оценки…», «Ищу фильмы…» |
| `check` | после ответа модели, до сборки `AgentResponse` | «Проверяю подборку…» |

Правила:

1. Первое событие `classify` отправляется до обращения к модели — интерфейс обязан показать реакцию не позже 1 с (NFR-AG-17).
2. `text` — готовая фраза для пользователя, без параметров и без названий инструментов. Перечень фраз — [110 модуля агентов](../agents/110.ui-ux.md).
3. События не входят в `AgentResponse`, не дублируются в `trace` и не сохраняются в историю диалога.
4. Для одного сообщения допустимо несколько `tool`; порядок и количество определяет агент.
5. Новый `step` — изменение контракта (major) и запись в ADR.

SSE-формат события описан в [130 модуля интерфейса](../ui/130.api-contracts.md): `event: progress`, `data: {"step": "tool", "text": "Ищу фильмы…"}`.

## 4. Служебные сообщения и согласие

### 4.1. `/start`

`/start` — часть контракта API-слоя и оркестратора. API-слой отправляет его при открытии страницы после `GET /api/v1/session`.

1. Оркестратор обрабатывает `/start` до классификатора; модель и агент не вызываются.
2. Ответ — приветствие для текущего этапа: `consent`, `onboarding` или `dialog`. На этапе `dialog` приветствие учитывает неоценённый выбор (`type = feedback_question`, US-09).
3. `/start` не попадает в `messages`, в `shown_ids` и в `AgentTrace`.
4. Других служебных команд нет. Сообщение, начинающееся с `/`, кроме точного `/start`, обрабатывается как обычный текст (классификатор увидит его как `off_topic`, если это не про кино).

### 4.2. Согласие

Единая функция оркестратора:

```python
async def set_consent(user_id: str, accepted: bool) -> AgentResponse
```

Два способа, оба ведут в неё:

| Способ | Вход | Что происходит |
|---|---|---|
| Кнопка в интерфейсе | `POST /api/v1/consent {"accepted": true}` | `accepted=true` → сохраняется `users.consent_at`, этап `onboarding`, ответ просит город |
| Текст в чате на этапе `consent` | классификатор этапа вернул `yes`/`no` | то же; модель к согласию не допускается |

При `accepted = false` ничего не сохраняется, этап остаётся `consent`, ответ показывает правила снова. Текст правил — [110 модуля агентов](../agents/110.ui-ux.md#2-текст-согласия).

## 5. Сколько фильмов в ответе

1. Агент показывает три фильма.
2. Меньше — только если `find_movies` вернул меньше трёх подходящих: агент показывает сколько есть и предлагает ослабить критерии.
3. Если найдено 0 — ответ без карточек, с предложением изменить пожелания.
4. В `AgentOutput.movie_ids` допускается 0–3 элемента; проверка ответа требует ровно три, если поиск вернул не меньше трёх.
5. Любой `movie_id` вне результатов `find_movies` текущего хода — ошибка проверки: один повтор, затем `LLM_INVALID_OUTPUT`.
6. Фильм длиннее `available_minutes` из контекста — тоже ошибка проверки. Свободное время не ослабляется.
7. Фильм с жанром из `genre_avoid` — тоже ошибка проверки. Запрещённые жанры не ослабляются.

## 6. Ошибки

Единственная таблица кодов. Документы модулей ссылаются сюда и не заводят собственных кодов.

| Код | Источник | Кто получает | Транспорт | Ретрай | Текст пользователю |
|---|---|---|---|---|---|
| `INVALID_PARAM` | данные | модель (исправляет вызов) | результат инструмента | нет | не показывается |
| `UNKNOWN_GENRE` | данные | модель | результат инструмента | нет | не показывается |
| `NOT_FOUND` | данные | модель | результат инструмента | нет | не показывается |
| `CITY_NOT_FOUND` | данные | пользователь | `AgentResponse.error` / 404 | нет | «Не нашёл такой город. Напишите название ещё раз.» |
| `CATALOG_EMPTY` | данные | пользователь | `AgentResponse.error` / 503 | нет | «Каталог фильмов пуст. Запустите загрузку каталога.» |
| `DATA_UNAVAILABLE` | данные | пользователь | `AgentResponse.error` | нет | «База данных недоступна. Попробуйте позже.» |
| `LLM_UNAVAILABLE` | агенты | пользователь | `AgentResponse.error` / SSE `error` | один повтор запроса к модели | «Сервис подбора временно недоступен. Попробуйте через минуту.» |
| `LLM_INVALID_OUTPUT` | агенты | пользователь | `AgentResponse.error` / SSE `error` | один повтор | «Не получилось подобрать фильмы. Попробуйте переформулировать запрос.» |
| `LIMIT_EXCEEDED` | агенты | пользователь | `AgentResponse.error` / SSE `error` | нет | «Подбор занял слишком много времени. Попробуйте уточнить запрос.» |
| `INPUT_TOO_LONG` | агенты | пользователь | `AgentResponse.error` / 400 | нет | «Сообщение длиннее 1000 символов. Сократите его.» |
| `INVALID_INPUT` | API | пользователь | 400 | нет | «Пустое сообщение.» |
| `AGENT_TIMEOUT` | API | пользователь | SSE `error` | нет | «Агент не ответил. Попробуйте ещё раз.» |
| `SESSION_BUSY` | API | пользователь | 409 | нет | «Дождитесь ответа на предыдущее сообщение.» |

Правила:

1. Ошибки, которые возвращаются модели (`INVALID_PARAM`, `UNKNOWN_GENRE`, `NOT_FOUND`), пользователю не показываются: модель получает их как результат инструмента и исправляет вызов.
2. Остальные коды показываются дословно текстом из таблицы. Других текстов ошибок в коде нет: запрет на «выдуманное» сообщение вместо ошибки зафиксирован в [110](../agents/110.ui-ux.md) и ADR-035.
3. Каждая ошибка пишется в журнал полями: `event=error`, `code`, `layer`, `user_id`, `stage`, `duration_ms`, `retry` (bool). Текст сообщения пользователя в журнал не попадает.
4. `error_code` в `AgentResponse` заполняется только при `type = "error"`; для HTTP-ответов API-слой использует то же значение.
5. `SESSION_BUSY` — следствие правила «один активный ход на пользователя» ([146](../agents/146.logic-scheme.md)); подтверждение поведения API-слоя — в [130 модуля интерфейса](../ui/130.api-contracts.md).

## 7. Инструменты

Полные сигнатуры, результаты и ошибки — [130 модуля данных](../data/130.api-contracts.md). Общие правила:

1. Инструменты вызываются только из процесса backend, REST у модуля данных нет.
2. `user_id` подставляет код; модель его не передаёт и не видит.
3. `exclude_ids` подставляет оркестратор из `shown_ids` (все показанные в сессии, до 50); модель этот параметр не передаёт. `last_shown_ids` используется только для проверки `save_choice`. Оценённые пользователем фильмы `find_movies` исключает сама.
4. Все параметры `find_movies` необязательные. Без критериев функция возвращает фильмы по убыванию рейтинга с учётом исключений.
5. `save_choice` принимает только фильм из последней подборки; иное — ошибка, которую видит модель.
6. `exclude_genres` в `find_movies` реестр инструментов объединяет с `SessionState.context.genre_avoid`: модель может добавить жанры, но не может снять запрет пользователя.
7. Инструмента удаления данных у агента нет; согласие, город и удаление — только код оркестратора.
