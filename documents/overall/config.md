# Конфигурация CineMatch

*Общая часть. Единственный источник списка переменных окружения и тайм-аутов.*

`.env.example` в корне репозитория строится по таблице 1 и не содержит других переменных. Документы модулей ссылаются сюда и не повторяют значения.

## 1. Переменные окружения

| Переменная | Обязательна | Значение по умолчанию | Кто читает | Что при отсутствии |
|---|---|---|---|---|
| `TMDB_API_KEY` | да | — | модуль данных | backend не стартует, в журнале `CONFIG_MISSING TMDB_API_KEY` |
| `CINEMATCH_DB_PATH` | нет | `/data/cinematch.db` в контейнере, `storage/cinematch.db` локально | модуль данных | берётся значение по умолчанию |
| `CINEMATCH_USER_ID` | нет | `web:local` | API-слой | берётся значение по умолчанию |
| `LLM_BASE_URL` | нет | `https://routerai.ru/api/v1` | модуль агентов | берётся значение по умолчанию |
| `LLM_API_KEY` | да | — | модуль агентов | backend не стартует, в журнале `CONFIG_MISSING LLM_API_KEY` |
| `LLM_MODEL` | да | — | модуль агентов | backend не стартует, в журнале `CONFIG_MISSING LLM_MODEL` |
| `LLM_CLASSIFIER_MODEL` | нет | значение `LLM_MODEL` | модуль агентов | используется `LLM_MODEL` |
| `LLM_TIMEOUT_S` | нет | `20` | модуль агентов | 20 с |
| `TURN_TIMEOUT_S` | нет | `45` | модуль агентов | 45 с |
| `AGENT_TIMEOUT_S` | нет | `60` | API-слой | 60 с |

Правила:

1. Обязательные переменные проверяются при старте backend. Отсутствие обязательной переменной — остановка с понятным сообщением, а не падение на первом запросе.
2. Файл базы называется `cinematch.db` во всех окружениях. В контейнере он лежит в томе `/data`, локально — в `storage/`.
3. Переменных `LLM_MODE`, `LLM_PROVIDER`, `TELEGRAM_BOT_TOKEN`, `CLI_USER_ID` в MVP нет: режим локальной модели, Telegram и CLI-клиент относятся к будущему функционалу. Появиться они могут только вместе с ADR.
4. Секреты (`TMDB_API_KEY`, `LLM_API_KEY`) не попадают в журнал, в трассу и в репозиторий (NFR-AG-08).
5. Значения по умолчанию продублированы в `docker-compose.yml`, чтобы `docker compose up` работал без `.env` для необязательных переменных.

## 2. Тайм-ауты и целевые значения

Целевые значения (NFR) проверяются тестами. Тайм-ауты обрывают работу в коде. Это разные вещи, и путать их нельзя.

| Параметр | Значение | Тип | Где задаётся | Где проверяется |
|---|---|---|---|---|
| Классификация запроса | ≤ 2 с | цель (NFR-AG-03) | — | TS-AG-08 |
| Ответ на одно сообщение | ≤ 10 с для 95 % сообщений | цель (NFR-AG-01) | — | TS-AG-08 |
| Полный подбор, включая ответы пользователя | ≤ 60 с | цель (NFR-AG-02) | — | TS-AG-08 |
| Первое событие `progress` | ≤ 1 с | цель (NFR-AG-17) | — | TS-AG-08 |
| Один запрос к RouterAI | 20 с | тайм-аут | `LLM_TIMEOUT_S` | клиент модели |
| Обработка одного сообщения оркестратором | 45 с | тайм-аут | `TURN_TIMEOUT_S` | оркестратор |
| Ожидание ответа агента в API-слое | 60 с | тайм-аут | `AGENT_TIMEOUT_S` | API-слой |

Условие согласованности: `LLM_TIMEOUT_S < TURN_TIMEOUT_S < AGENT_TIMEOUT_S`.

Порядок срабатывания:

1. Запрос к модели не уложился в 20 с — один повтор, затем `LLM_UNAVAILABLE`.
2. Ход не уложился в 45 с — оркестратор возвращает `LIMIT_EXCEEDED`.
3. API-слой не дождался ответа за 60 с — прерывает поток событием `error` с кодом `AGENT_TIMEOUT`.

При таком порядке пользователь всегда получает понятное сообщение от оркестратора, а не оборванный поток: оркестратор успевает ответить раньше API-слоя.

Целевые значения должны быть меньше соответствующих тайм-аутов, иначе ошибка не покажется вовремя: 10 с ответа против 45 с хода и против 60 с ожидания.
