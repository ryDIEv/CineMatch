## Правила

1. **Основной функционал и будущий функционал.** Документ описывает MVP; в конце каждого документа — раздел «Будущий функционал».
2. **Сквозная нумерация** вариантов использования (UC), историй (US), эпиков (EP) и архитектурных решений (ADR) по всему проекту. Требования и тестовые сценарии — с префиксом модуля: `FR-AG-01`, `NFR-DB-01`, `TS-UI-01`. Будущий функционал — с буквой F: `UC-F1`, `EP-F1`.
3. **Диаграммы — UML.** Исходник PlantUML (`.puml`) и изображение (`.svg`) лежат в `diagrams/` модуля; в документ вставляется изображение.
4. **Неприменимые документы не удаляются:** в них указано, чем они заменены и почему.
5. **Язык** — русский, английские термины в скобках; имена в коде — на английском.
6. **Изменения** — через pull request; контракты между модулями (130–140) — с одобрения всех трёх ответственных.
