## Правила

1. **Одно значение — один документ.** Поля структур, коды и тексты ошибок, переменные окружения и тайм-ауты описаны только в `overall/`. Документы модулей (`120`, `130`, `165`, `075`) ссылаются на них и не дублируют значения.
2. **Основной функционал и будущий функционал.** Документ описывает MVP; в конце каждого документа — раздел «Будущий функционал».
3. **Сквозная нумерация** вариантов использования (UC), историй (US), эпиков (EP) и архитектурных решений (ADR) по всему проекту. Требования и тестовые сценарии — с префиксом модуля: `FR-AG-01`, `NFR-DB-01`, `TS-UI-01`. Будущий функционал — с буквой F: `UC-F1`, `EP-F1`.
4. **Диаграммы — UML.** Исходник PlantUML (`.puml`) и изображение (`.svg`) лежат в `diagrams/` модуля; в документ вставляется изображение. Диаграмма меняется вместе с текстом в одном PR.
5. **Неприменимые документы не удаляются:** в них указано, чем они заменены и почему.
6. **Язык** — русский, английские термины в скобках; имена в коде — на английском.
7. **Изменения** — через pull request; контракты между модулями (`overall/`, `130`–`140`) — с одобрения всех трёх ответственных.
8. **Проверка** — `python scripts/check_docs.py` перед каждым pull request.

## Как читать комплект

1. `overall/contracts.md` — что передаётся между модулями.
2. `overall/config.md` — чем конфигурируется.
3. `overall/build.md` — из каких файлов состоит код и в каком порядке собирается.
4. Документ своего модуля — по блокам A–I.
5. `125.prompts.md` и `110.ui-ux.md` — дословные тексты (только модуль агентов).
