## 1. Взаимодействие компонентов

```
API-слой
  └─ handle_user_turn ──► Оркестратор
                            ├─ Загрузчик промптов ──► prompts/*.md
                            ├─ Классификатор ──► Клиент модели
                            ├─ Агент ──┬─ Реестр инструментов ──► модуль данных
                            │          └─ Клиент модели ──► RouterAI
                            ├─ Проверка ответа
                            ├─ Прогресс ──► on_progress ──► SSE
                            ├─ Трасса
                            └─ Журнал
```

Правила:

1. Модуль данных вызывается только через реестр инструментов; прямых импортов его репозиториев в агенте нет.
2. Клиент модели — единственное место с ключом и тайм-аутом; он же считает вызовы (≤ 8) и токены.
2a. Блокировка хода — единственное место, где решается `SESSION_BUSY`; API-слой читает тот же признак, но не создаёт второй lock.
3. Проверка ответа не вызывает модель: она либо принимает, либо возвращает ошибку для одного повтора.
4. Прогресс не знает о SSE: он вызывает функцию, переданную API-слоем.

## 2. Пороги и лимиты в компонентах

| Компонент | Проверка | Значение |
|---|---|---|
| Оркестратор | длина входа | 1000 символов |
| Проверка ответа | длина текста | 1200 символов |
| Проверка ответа | длина объяснения | 240 символов |
| Проверка ответа | фильмов в подборке | 3 (меньше — только при нехватке результатов) |
| Клиент модели | вызовов на сообщение | 8 |
| Клиент модели | тайм-аут запроса | `LLM_TIMEOUT_S` |
| Оркестратор | тайм-аут хода | `TURN_TIMEOUT_S` |
| Блокировка хода | время жизни | `TURN_TIMEOUT_S`, снятие в `finally` |

Значения — [overall/config.md §2](../overall/config.md#2-тайм-ауты-и-целевые-значения), пределы — [overall/contracts.md §8](../overall/contracts.md#8-пределы).
