# 050 — Entities + Lifecycle

*CineMatch. Модуль ИИ-агентов* | [оглавление модуля](README.md)

![Сущности модуля ИИ-агентов](diagrams/050-classes.svg)

Модуль агентов создаёт и использует эти сущности; хранит их модуль данных ([120 Data Model модуля данных](../data/120.data-model.md)).

| Сущность | Атрибуты | Ограничения |
|---|---|---|
| DialogSession | `stage`, `pending`, `messages`, `context`, `last_shown_ids`, `shown_ids`, `clarifications_asked`, `updated_at` | Одна на пользователя; удаляется через 24 часа без активности; в `messages` — не более 20 последних сообщений |
| EveningContext | `mood`, `energy`, `available_minutes`, `company`, `genre_wishes`, `genre_avoid`, `notes` | Значения из перечней ([120](120.data-model.md)) |
| AgentOutput | `kind`, `text`, `movie_ids`, `reasons` | `movie_ids` пуст или содержит ровно три фильма из результатов `find_movies` текущего хода |
| AgentTrace | `step`, `action`, `summary` | Без системных промптов и ключей |
| AgentResponse | `type`, `text`, `movies`, `trace`, `stage` | Проверяется по схеме перед отдачей |
| Choice | `movie_id`, `status` | Не более одного выбора со статусом `pending` |
| WatchMark (оценка) | `movie_id`, `rating` 1–10, `mood_match`, `source` | Одна оценка на фильм; повторная заменяет прежнюю |

**Жизненный цикл сессии диалога.** Этапы задают только инварианты, которые проверяет код. Внутри этапа `dialog` ход разговора определяет агент.

![Жизненный цикл сессии](diagrams/050-state-session.svg)

| Этап | Описание | Переход |
|---|---|---|
| `consent` | Показ правил хранения данных | Согласие → `onboarding`; отказ — этап сохраняется, данные не записываются |
| `onboarding` | Пользователь называет город | Город найден и подтверждён → `dialog` |
| `dialog` | Разговор с агентом: подбор, реакции, оценки | Классификатор вернул `delete_data` → `confirm_delete` |
| `confirm_delete` | Ожидание подтверждения удаления | Подтверждение → данные удалены, следующий визит начинается с `consent`; отказ → `dialog` |

Поле `pending` хранит неоценённый выбор: при новом визите оркестратор передаёт агенту указание спросить оценку.

### Будущий функционал

Сущности `Reminder` и `Subscription` для агента-планировщика.
