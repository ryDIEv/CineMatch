# 145 — ADR

*CineMatch. Модуль ИИ-агентов* | [оглавление модуля](README.md)

Нумерация сквозная: ADR-001…ADR-010 — модуль агентов, ADR-011…ADR-018 — [модуль данных](../data/145.architecture-decisions.md), ADR-019…ADR-024 — [модуль интерфейса](../ui/145.architecture-decisions.md).

**ADR-001. Агент — модель с вызовом инструментов.** *Принято.* Контекст: требование «агенты, а не скрипты». Решение: в каждом агенте модель сама выбирает вызовы инструментов, код исполняет их и проверяет результат. Последствия: (+) соответствие определению агента, гибкость; (−) больше запросов к модели и задержка (NFR-AG-01).

**ADR-002. Оркестратор — обычный код.** *Принято.* Контекст: маршрутизация по этапу диалога не требует рассуждений. Решение: явная машина состояний ([050](050.entities.md)). Последствия: (+) предсказуемость, простая отладка; (−) новые этапы добавляются в код вручную.

**ADR-003. Модель выбирает критерии, фильмы возвращает база данных.** *Принято.* Контекст: модели выдумывают фильмы и факты. Решение: модель формирует только параметры `find_movies`. Последствия: (+) только реальные фильмы; (−) качество ограничено полнотой каталога.

**ADR-004. OpenRouter как единый LLM-шлюз.** *Предложено.* Контекст: прямые зарубежные API сложно оплатить из России; модель может понадобиться сменить. Решение: OpenRouter по API, совместимому с OpenAI. Последствия: (+) смена модели в конфигурации; (−) зависимость от одного шлюза.

**ADR-005. Классификатор намерений с закрытым перечнем.** *Принято.* Контекст: пользователь пишет свободно. Решение: короткий вызов модели возвращает одно значение `Intent`; при `off_topic` агенты не вызываются. Последствия: (+) свободный ввод без меню, меньше поверхность атаки; (−) лишний вызов модели (NFR-AG-03).

**ADR-006. Шкала оценок 1–10.** *Принято.* Контекст: пользователи говорят «7 из 10»; рейтинг TMDB тоже 10-балльный. Последствия: (+) естественно и сопоставимо с каталогом.

**ADR-007. Только свободный текст; карточка формирует сообщение.** *Принято.* Контекст: проект строится вокруг агента; кнопки-варианты сводят его к меню. Решение: агент не предлагает кнопок; нажатие на карточку отправляет обычное сообщение «Выбираю «…»» с подсказкой `movie_id`, решение принимает агент. Последствия: (+) естественный диалог; (−) возможны ошибки классификации — компенсируются уточнением.

**ADR-008. Минимальные права агентов на инструменты.** *Принято.* Контекст: модель может быть обманута текстом пользователя. Решение: у каждого агента свой список инструментов, проверка кодом; `user_id` и исключения подставляет код. Последствия: (+) ошибка модели не приводит к действиям вне роли агента.

**ADR-009. Трасса решений в ответе.** *Принято.* Контекст: пользователю и руководителю важно видеть, что решения принимает агент. Решение: `AgentResponse.trace` с понятным описанием вызовов. Последствия: (+) прозрачность, удобная отладка и демонстрация; (−) нужно следить, чтобы в трассу не попали служебные данные.

**ADR-010. Разработка по спецификации с ИИ-агентом программирования.** *Предложено.* Контекст: руководитель рекомендует разработку с ИИ-агентами. Решение: документы каталога `documents/` — источник спецификаций для Spec Kit; код пишет OpenCode, каждое изменение проходит ревью через pull request. Последствия: (+) скорость и трассируемость от требования до кода; (−) риск непонятного команде кода — снижается обязательным ревью.
