# 130 — API Contracts

*CineMatch. Модуль ИИ-агентов* | [оглавление модуля](README.md)

Модуль работает в процессе backend и вызывается API-слоем как функция Python. Структуры, коды ошибок и пределы — в [общем контракте](../overall/contracts.md); здесь только функция хода и схемы инструментов. Версия контракта — `0.4.0`.

## 1. Функция хода

```python
async def handle_user_turn(
    user_id: str,
    message: str,
    movie_id: int | None = None,
    on_progress: Callable[[str, str], None] | None = None,
) -> AgentResponse
```

| Параметр | Назначение |
|---|---|
| `user_id` | пользователь; подставляется API-слоем, модель его не видит |
| `message` | текст сообщения; `/start` — служебное, остальное проходит обработку |
| `movie_id` | подсказка при нажатии на карточку; решение о реакции принимает агент |
| `on_progress` | приёмник событий хода; вызывается оркестратором, API-слой перекладывает их в SSE |

Правила:

1. Один вызов — один ход. Параллельные ходы для одного пользователя не допускаются: второй запрос получает `SESSION_BUSY` ([contracts.md §6](../overall/contracts.md#6-ошибки)).
2. События `progress` формирует оркестратор (ADR-030), шаги и фразы — [contracts.md §3](../overall/contracts.md#3-сообщения-о-ходе-работы) и [110 §4](110.ui-ux.md#4-фразы-хода-работы). В `AgentResponse` события не попадают.
3. `/start` обрабатывается до классификатора и модели (ADR-031); ответ — приветствие этапа. Поведение — [146 §3](146.logic-scheme.md#3-служебное-сообщение-start).
4. Согласие принимается функцией `set_consent` (раздел 2), а не сообщением агента (ADR-033).
5. Ошибки возвращаются как `AgentResponse(type="error")` с `error_code` из общего каталога; тексты не дублируются в модуле.

## 2. Согласие

```python
async def set_consent(user_id: str, accepted: bool) -> AgentResponse
```

| Вход | Что происходит | Ответ |
|---|---|---|
| `accepted=True` | сохраняется `users.consent_at`, этап → `onboarding` | `type=question`, просьба назвать город |
| `accepted=False` | ничего не сохраняется, этап остаётся `consent` | `type=consent`, правила показываются снова |

Вызывается из API-слоя (`POST /api/v1/consent`) или оркестратором, когда на этапе `consent` локальный `parse_consent` вернул `yes`/`no` (ADR-033, ADR-043). Модель к согласию не допускается.

## 4. Инструменты агента

Описываются функциями Python с аннотациями типов; Pydantic AI строит из них JSON Schema, совместимую с OpenAI. Полные сигнатуры, результаты и ошибки — [130 модуля данных](../data/130.api-contracts.md).

| Инструмент | Параметры от модели | Подставляет код | Возвращает | Ошибки (модели) |
|---|---|---|---|---|
| `extract_context` | `message` | — | `EveningContext` | `INVALID_PARAM` |
| `get_user_ratings` | `limit` | `user_id` | до `limit` оценок, по убыванию даты | `INVALID_PARAM` |
| `get_user_profile` | — | `user_id` | веса жанров и актёров, `ratings_count` | — |
| `get_weather` | — | `user_id` | `{city, condition, temp_c, is_day}` или `None` | — |
| `find_movies` | `genres`, `exclude_genres`, `year_from`, `year_to`, `min_rating`, `max_runtime`, `limit` | `user_id`, `exclude_ids` | до `limit` карточек; порядок — по числу совпавших жанров, затем по рейтингу | `INVALID_PARAM`, `UNKNOWN_GENRE` |
| `get_movie_with_credits` | `movie_id` | — | карточка + `actors`, `overview` | `NOT_FOUND` |
| `search_movie` | `title`, `year` | — | до 5 совпадений | `INVALID_PARAM` |
| `save_choice` | `movie_id` | `user_id`; проверка по `last_shown_ids` | `{choice_id}` | `INVALID_PARAM`, `NOT_FOUND` |
| `save_rating` | `movie_id`, `rating`, `mood_match` | `user_id`, `source` | `{saved, closed_choice_id}` | `INVALID_PARAM`, `NOT_FOUND` |
| `close_choice` | — | `choice_id` из `pending`; `status="dismissed"` | `{closed: true}` | `NOT_FOUND` |

Правила:

1. `user_id` и `exclude_ids` модель не передаёт и не видит — их подставляет реестр инструментов (ADR-008). `exclude_genres` модель может передать, но реестр объединяет его с `SessionState.context.genre_avoid`, поэтому снять запрет пользователя нельзя.
2. `find_movies` исключает фильмы, оценённые пользователем, сама; `exclude_ids` — только показанные в текущей сессии (ADR-036).
3. Все параметры `find_movies` необязательные. Без критериев функция возвращает фильмы по убыванию рейтинга с учётом исключений; при переданных жанрах — по числу совпавших жанров, затем по рейтингу (ADR-036).
4. `save_choice` принимает только фильм из последней подборки; иное — ошибка, которую видит модель и исправляет вызов.
5. Ошибка инструмента возвращается модели как результат `{"error": {"code": ..., "message": ...}}` и пользователю не показывается.
6. `mood_match` — `yes`, `partly`, `no` или `null`; `source` — `after_choice` или `manual`.
7. `AgentOutput.kind` переходит в `AgentResponse.type` один в один; `consent` и `error` формирует только оркестратор. Шаги и формулировки трассы задаёт код по таблице [contracts §2.7](../overall/contracts.md#27-agenttrace--шаг-трассы).

### 4.1. Схема `find_movies`, которую получает модель

```json
{
  "type": "function",
  "function": {
    "name": "find_movies",
    "description": "Найти фильмы по критериям. Жанры объединяются по ИЛИ, выше идут фильмы с большим числом совпавших жанров, затем по рейтингу. Уже показанные в сессии и оценённые пользователем исключаются автоматически. Все параметры необязательные.",
    "parameters": {
      "type": "object",
      "properties": {
        "genres": {"type": "array", "items": {"type": "string"}, "maxItems": 5, "description": "Желаемые жанры (genre_wishes), русские названия из справочника; достаточно совпадения с одним"},
        "exclude_genres": {"type": "array", "items": {"type": "string"}, "maxItems": 5, "description": "Запрещённые жанры (genre_avoid); фильм с любым из них не возвращается"},
        "year_from": {"type": "integer", "minimum": 1900},
        "year_to": {"type": "integer", "maximum": 2030},
        "min_rating": {"type": "number", "minimum": 0, "maximum": 10},
        "max_runtime": {"type": "integer", "minimum": 30, "maximum": 600, "description": "Максимальная длительность в минутах"},
        "limit": {"type": "integer", "minimum": 3, "maximum": 30, "default": 15}
      },
      "required": []
    }
  }
}
```

## 5. Классификатор

| Этап | Промпт | Возможные значения |
|---|---|---|
| `dialog` | `classifier.md` | `cinema`, `delete_data`, `off_topic`, `unsafe` |
| `confirm_delete` | `confirm_yes_no.md` | `yes`, `no` |
| `consent` | не вызывается: `parse_consent` | `yes`, `no` |

Тексты — [125 §3–4](125.prompts.md#3-classifiermd). Невалидный ответ классификатора — один повтор, затем безопасное поведение: `cinema` не вызывается, пользователь получает отказ по теме (ADR-005).

## 6. Изменения версии

| Версия | Что изменилось |
|---|---|
| `0.4.0` | `city_options` в `SessionState`; текстовое согласие разбирает код; данные для промпта агент получает инструментами; `null`/`[]` в жанровых списках; порядок `find_movies` по совпавшим жанрам; уточнены `exclude_genres`, `close_choice`, проверка `genre_avoid` |
| `0.3.0` | `on_progress(step, text)`; `/start` как часть контракта; `set_consent`; `movies` → `RecommendedMovie[]`; все параметры `find_movies` необязательные; `find_movies.exclude_genres`, жанры по ИЛИ; единый `error_code` из общего каталога |
| `0.2.0` | базовая версия: `AgentResponse`, десять инструментов, трасса |

Правила совместимости — [contracts.md §1](../overall/contracts.md#1-правила-версионирования).

## 7. Будущий функционал

Параметр `source` во входе (`web`, `telegram`); инструменты агента-планировщика; потоковая передача токенов модели (сейчас потоковыми являются только события хода).
