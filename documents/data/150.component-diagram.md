## 1. Правила компонентов

1. SQL живёт только в `repositories/` и `db.py`; `api.py` вызывает репозитории и не строит запросы.
2. Клиенты внешних систем — только в модуле данных. Другие модули не обращаются к TMDB и Open-Meteo ([020](020.system-context.md)).
3. `api.py` — единственная точка входа: функции этого файла импортирует модуль агентов и API-слой. Репозитории наружу не экспортируются.
4. Проверка параметров — в `api.py` до вызова репозитория; репозитории получают уже проверенные значения (ADR-015).
5. Транзакция открывается в `api.py` (одна на функцию записи) и передаётся в репозитории параметром сессии.
6. Клиенты не знают о базе: TMDB отдаёт нормализованные словари, запись выполняет репозиторий каталога.
7. `scripts/load_catalog.py` — тонкая обёртка: разбор аргументов, вызов `ingest_movies`, печать отчёта, коды завершения. Логики загрузки в скрипте нет.

## 2. Порядок инициализации

1. `config.py` читает `TMDB_API_KEY`, `CINEMATCH_DB_PATH` ([config.md](../overall/config.md)).
2. `db.py` создаёт движок и включает `PRAGMA`.
3. `alembic upgrade head` — схема готова.
4. `purge_expired()` — очистка сессий.
5. Регистрация инструментов агента — реестр получает ссылки на функции `api.py`.
