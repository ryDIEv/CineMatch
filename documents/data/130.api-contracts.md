# 130 — API Contracts

*CineMatch. Модуль данных* | [оглавление модуля](README.md)

Модуль предоставляет функции Python в процессе backend; REST API у модуля нет. Структуры, коды ошибок и пределы — в [общем контракте](../overall/contracts.md); здесь сигнатуры, проверки параметров, семантика SQL и запросы к внешним системам. Версия функций — `0.1.0`.

Кто вызывает функции — [070](070.role-matrix.md), схема таблиц — [120](120.data-model.md), порядок шагов — [146](146.logic-scheme.md).

## 1. Общие правила

1. Инструменты вызываются только агентом (через реестр `cinematch/agents/tools.py`), служебные функции — оркестратором, API-слоем и скриптом загрузки. Модель не видит служебных функций.
2. `user_id` подставляет код; модель его не передаёт ([contracts §7](../overall/contracts.md#7-инструменты)). `exclude_ids` подставляет оркестратор из `SessionState.shown_ids` — все фильмы, показанные пользователю в сессии (до 50).
3. Каждый параметр проверяется по типу и диапазону до SQL. Неверный параметр — `ToolError("INVALID_PARAM", …)`, который модель получает как результат инструмента и исправляет вызов.
4. SQL собирается только через SQLAlchemy Core/ORM с подстановкой параметров; конкатенация значений в строку запроса запрещена (NFR-DB-11).
5. Запись — в транзакции. Чтение — без явной транзакции; SQLite в WAL не блокирует читателей писателем.
6. Значения `None` означают «критерий не задан» и в SQL не подставляются. Пустой список жанров равнозначен `None`.
7. Все временные метки — ISO 8601 UTC (`2026-11-08T18:15:00Z`), см. [120 §1](120.data-model.md#1-файл-базы-и-параметры-подключения).

## 4. Описание функций

Разделы 4.1–4.9 — инструменты агента, 4.10–4.19 — служебные функции. У инструментов проверяются параметры, пришедшие от модели; у служебных — параметры, пришедшие от кода.

### 4.1. `get_user_ratings`

```python
def get_user_ratings(user_id: str, limit: int = 20) -> list[RatedMovie]
```

| Параметр | Проверка | По умолчанию |
|---|---|---|
| `limit` | целое 1…50 | 20 |

Возвращает оценки пользователя по убыванию `rated_at`; для каждой — `movie_id`, `title`, `year`, `genres` (русские названия по правилу [120 §4](120.data-model.md#4-genres-movie_genres-people-movie_cast)), `rating`, `mood_match`, `rated_at`. Пустой список — у пользователя нет оценок.

### 4.2. `get_user_profile`

```python
def get_user_profile(user_id: str) -> PreferenceProfile
```

Считается при каждом вызове по **всем** оценкам пользователя; таблицы профиля нет ([ADR-013](145.architecture-decisions.md#adr-013)). Формула и пример — ADR-013. `limit` из `get_user_ratings` на профиль не влияет: он ограничивает только то, что видит модель.

Холодный старт (нет оценок): `{"genre_weights": {}, "actor_weights": {}, "ratings_count": 0}`.

### 4.3. `get_weather`

```python
def get_weather(user_id: str) -> Weather | None
```

`None`, если у пользователя нет города или сервис недоступен. Структура и коды — §8. Ошибок не возвращает: погода — подсказка, а не условие подбора; отказ сервиса не должен ломать ход.

### 4.4. `find_movies`

```python
def find_movies(
    *, user_id: str,
    genres: list[str] | None = None,
    exclude_genres: list[str] | None = None,
    year_from: int | None = None,
    year_to: int | None = None,
    min_rating: float | None = None,
    max_runtime: int | None = None,
    exclude_ids: list[int] | None = None,
    limit: int = 15,
) -> list[MovieCard]
```

| Параметр | Проверка | Ошибка | Смысл в SQL |
|---|---|---|---|
| `genres` | 1–5 элементов, каждый — непустая строка ≤ 40 символов | `INVALID_PARAM` | подзапрос совпадений: хотя бы один жанр, логика **ИЛИ**; число совпадений задаёт порядок |
| `genres` (неизвестное название) | после нормализации нет строки в `genres.name_norm` | `UNKNOWN_GENRE` | — |
| `exclude_genres` | 1–5 элементов, те же проверки и нормализация, что у `genres` | `INVALID_PARAM` / `UNKNOWN_GENRE` | по одному `NOT EXISTS` на жанр: фильм с любым из запрещённых жанров отбрасывается |
| `year_from` | целое 1900…2030 | `INVALID_PARAM` | `movies.year >= :year_from` |
| `year_to` | целое 1900…2030, `year_from ≤ year_to`, если заданы оба | `INVALID_PARAM` | `movies.year <= :year_to` |
| `min_rating` | число 0…10 | `INVALID_PARAM` | `movies.rating >= :min_rating` |
| `max_runtime` | целое 30…600 | `INVALID_PARAM` | `movies.runtime <= :max_runtime`; фильмы без длительности отбрасываются |
| `exclude_ids` | 0…50 целых; подставляет код, не модель | `INVALID_PARAM` | `movies.id NOT IN (:exclude_ids)` |
| `limit` | целое 3…30 | `INVALID_PARAM` | `LIMIT :limit` |

Правила:

1. Все параметры необязательные. Без критериев функция возвращает фильмы по убыванию рейтинга с учётом исключений и порога голосов ([contracts §7](../overall/contracts.md#7-инструменты)).
2. Оценивавшийся пользователем фильм исключается всегда — подзапросом по `user_ratings`, независимо от `exclude_ids`.
3. Жанры объединяются логикой **ИЛИ**: запрос «комедия, мелодрама» вернёт фильмы хотя бы с одним из жанров. Число совпавших жанров влияет на порядок — фильм с двумя совпадениями выше фильма с одним при прочих равных.
4. Названия жанров нормализуются (`lower`, `ё → е`), поэтому «Комедия», «комедия» и «комедии» — одно и то же. Список допустимых названий — `SELECT name FROM genres ORDER BY tmdb_id`.
5. Порядок — `COALESCE(matched, 0) DESC, rating DESC, vote_count DESC, id ASC`. Первым идёт число совпавших жанров, затем рейтинг; `id` стабилизирует выдачу при полном равенстве, иначе тесты невоспроизводимы.
6. Пустой результат — `[]`, не ошибка. Решение «меньше трёх» принимает агент ([contracts §5](../overall/contracts.md#5-сколько-фильмов-в-ответе)). Пустой `exclude_ids` — условие `NOT IN` не добавляется; пустой `genres` равнозначен `None`.
7. Пустой каталог (в `movies` нет строк) — исключение `ServiceError(CATALOG_EMPTY)`; пользователь получает текст из [contracts §6](../overall/contracts.md#6-ошибки), модель не вызывается.
8. Значения `poster_url` и `age_rating` могут быть `null`; агент не должен на них опираться при отборе.
9. `exclude_genres` — это `genre_avoid` из контекста: агент передаёт запрещённые жанры, код отбрасывает фильмы с любым из них. Проверка и нормализация те же, что у `genres`; неизвестный жанр в `exclude_genres` — `UNKNOWN_GENRE`, чтобы модель не думала, что запрет применился. Пустой список равнозначен `None`.

Запрос, который выполняет функция ([120 §2](120.data-model.md#2-схема) — схема и индексы):

```sql
SELECT m.id, m.tmdb_id, m.title, m.year, m.runtime, m.rating,
       m.vote_count, m.age_rating, m.poster_path,
       COALESCE(gm.matched, 0) AS matched
FROM movies AS m
LEFT JOIN (
    SELECT mg.movie_id, COUNT(*) AS matched
    FROM movie_genres AS mg
    JOIN genres AS g ON g.id = mg.genre_id
    WHERE g.name_norm IN (:genre_1, :genre_2, …)   -- переданные genres
    GROUP BY mg.movie_id
) AS gm ON gm.movie_id = m.id
WHERE m.rating IS NOT NULL
  AND m.vote_count >= 100                       -- порог голосов, §5
  AND (:min_rating  IS NULL OR m.rating >= :min_rating)
  AND (:max_runtime IS NULL OR (m.runtime IS NOT NULL AND m.runtime <= :max_runtime))
  AND (:year_from   IS NULL OR m.year >= :year_from)
  AND (:year_to     IS NULL OR m.year <= :year_to)
  AND m.id NOT IN (SELECT movie_id FROM user_ratings WHERE user_id = :user_id)
  AND m.id NOT IN :exclude_ids
  AND (:genres_count = 0 OR gm.matched > 0)
  AND NOT EXISTS (SELECT 1 FROM movie_genres mg2 JOIN genres g2 ON g2.id = mg2.genre_id
                  WHERE mg2.movie_id = m.id AND g2.name_norm = :exclude_genre_1)
  -- … по одному NOT EXISTS на каждый переданный exclude_genres
ORDER BY matched DESC, m.rating DESC, m.vote_count DESC, m.id ASC
LIMIT :limit;
```

Без `genres` подзапрос `gm` не выполняется: `matched = 0` у всех строк, порядок задаёт рейтинг. План запроса опирается на `ix_movies_rating` (частичный, `rating IS NOT NULL`) и `ix_movie_genres_genre`. Время — NFR-DB-01.

### 4.5. `get_movie_with_credits`

```python
def get_movie_with_credits(movie_id: int) -> MovieDetails
```

| Проверка | Ошибка |
|---|---|
| `movie_id` — целое > 0 | `INVALID_PARAM` |

Возвращает карточку, список имён первых 10 актёров (`movie_cast ORDER BY billing_order`) и `overview` (может быть `null`). Отдельная функция нужна потому, что `find_movies` не отдаёт актёров: они утяжеляют подборку из 15 карточек.

### 4.6. `search_movie`

```python
def search_movie(title: str, year: int | None = None) -> list[MovieSummary]
```

| Параметр | Проверка | Ошибка |
|---|---|---|
| `title` | строка 1…100 символов после обрезки | `INVALID_PARAM` |
| `year` | целое 1900…2030 или `None` | `INVALID_PARAM` |

Поиск по `title_norm` (`lower`, `ё → е`). Порядок: точное совпадение, затем совпадение с начала строки, затем вхождение подстроки; внутри группы — `vote_count DESC`. Не больше 5 результатов. Пусто — `[]`.

### 4.7. `save_choice`

```python
def save_choice(user_id: str, movie_id: int) -> dict  # {"choice_id": int}
```

| Проверка | Ошибка |
|---|---|
| `movie_id` — целое > 0 | `INVALID_PARAM` |
| фильм есть в `movies` | `NOT_FOUND` |
| фильм входит в `last_shown_ids` последней подборки | проверяет реестр инструментов до вызова; иначе `NOT_FOUND` |

В одной транзакции: прежний `pending` пользователя → `dismissed` с `closed_at = now`; вставляется новый `pending` с `chosen_at = now`. Возвращается `id` новой строки. Частичный уникальный индекс `ux_user_choices_pending` гарантирует «не более одного ожидающего» даже при гонке.

Проверка идёт по `last_shown_ids` **последней подборки**, а не текущего хода: пользователь выбирает фильм следующим сообщением, когда `last_shown_ids` уже сменились бы. Реестр инструментов сравнивает `movie_id` с `SessionState.last_shown_ids` до вызова `save_choice`; фильм из прошлых подборок (но не из последней) — `NOT_FOUND`.

### 4.8. `save_rating`

```python
def save_rating(*, user_id: str, movie_id: int, rating: int,
                source: str, mood_match: str | None = None) -> dict
```

| Параметр | Проверка | Ошибка |
|---|---|---|
| `movie_id` | целое > 0, фильм есть | `INVALID_PARAM` / `NOT_FOUND` |
| `rating` | целое 1…10 | `INVALID_PARAM` |
| `source` | `after_choice` или `manual` | `INVALID_PARAM` |
| `mood_match` | `yes`, `partly`, `no` или `None` | `INVALID_PARAM` |

В одной транзакции: upsert оценки по ключу `(user_id, movie_id)`; если у пользователя есть `pending` с этим `movie_id`, он переводится в `rated` с `closed_at = now`. Возврат — `{"saved": true, "closed_choice_id": <id или null>}`.

Повторная оценка того же фильма перезаписывает `rating`, `mood_match`, `source`, `rated_at`; история оценок одной строкой на фильм — так профиль не считает фильм дважды.

### 4.11. `save_consent`

```python
def save_consent(user_id: str, source: str) -> None
```

Создаёт строку `users` с `consent_at = now` и `source`; повторный вызов не перезаписывает `consent_at` и `created_at` (первое согласие — источник истины). `source` проверяется по `users.source`. Город не заполняется — его сохраняет `save_user_settings` на следующем этапе.

### 4.14. `get_session_state`, `save_session_state`, `clear_session_state`

```python
def get_session_state(user_id: str) -> SessionState | None
def save_session_state(user_id: str, state: SessionState) -> None
def clear_session_state(user_id: str) -> None
```

| Функция | Поведение |
|---|---|
| `get_session_state` | читает `sessions.state_json`; просроченную или повреждённую строку удаляет и возвращает `None` ([120 §6](120.data-model.md#6-sessions)) |
| `save_session_state` | upsert; `expires_at = now + 24 ч`, `updated_at = now` — каждое сохранение продлевает сессию |
| `clear_session_state` | удаляет строку; отсутствие — не ошибка |

`SessionState` — модель из [contracts §2.5](../overall/contracts.md#25-sessionstate--состояние-диалога); модуль данных её не дополняет и не переписывает. До согласия сессии нет: `users` ещё не создан, а `sessions.user_id` — внешний ключ ([120 §6](120.data-model.md#6-sessions)). На этапе `consent` оркестратор не вызывает `save_session_state`.

### 4.15. `get_pending_feedback`

```python
def get_pending_feedback(user_id: str) -> PendingFeedback | None
```

Ищет строку `user_choices` со `status = 'pending'` и присоединяет карточку фильма: `{choice_id, movie: MovieCard, chosen_at}`. `None` — ожидающего выбора нет. Источник истины по неоценённому выбору — эта функция, а не `SessionState.pending` ([120 агентов §3](../agents/120.data-model.md#3-сессия-и-восстановление)).

### 4.16. `get_history`

```python
def get_history(user_id: str, limit: int = 50) -> list[HistoryItem]
```

| Параметр | Проверка |
|---|---|
| `limit` | целое 1…50 |

Объединяет оценки и выборы пользователя, сортирует по времени (`rated_at` / `chosen_at`) по убыванию, ограничивает `limit`. Формат элемента:

```json
{
  "kind": "rating",
  "movie": { "movie_id": 101, "tmdb_id": 447332, "title": "Тихий дом у моря",
             "year": 2014, "runtime": 98, "rating": 7.8, "vote_count": 1240,
             "age_rating": "12+", "genres": ["Драма", "Комедия"],
             "poster_url": "https://image.tmdb.org/t/p/w342/abc.jpg" },
  "rating": 7,
  "mood_match": "yes",
  "status": null,
  "at": "2026-11-07T21:40:00Z"
}
```

Для `kind = "choice"` поля `rating` и `mood_match` — `null`, `status` — `pending`, `rated` или `dismissed`. Выбор без оценки показывается в истории со статусом: экран должен уметь отличить «выбрал и не оценил».

### 4.17. `delete_user_data`

```python
def delete_user_data(user_id: str) -> dict
```

Одна транзакция: подсчёт строк в `user_ratings`, `user_choices`, `sessions`; удаление строки `users` (каскад удаляет остальное). Возврат:

```json
{"deleted_counts": {"user_ratings": 12, "user_choices": 3, "sessions": 1, "users": 1}}
```

Отсутствующий пользователь — нули во всех ключах, без ошибки: операция идемпотентна. Каталог не затрагивается ([120 §10](120.data-model.md#10-хранение-и-удаление)).

### 4.18. `purge_expired`

```python
def purge_expired() -> int
```

Удаляет `sessions` с `expires_at <= now`, возвращает число строк. Вызывается при старте backend ([build.md §3](../overall/build.md#3-порядок-старта-backend)).

### 4.19. `ingest_movies`

```python
def ingest_movies(pages: int = 500, from_year: int = 1970,
                  min_votes: int = 100, resume: bool = False) -> dict
```

| Параметр | Проверка | По умолчанию |
|---|---|---|
| `pages` | целое 1…500 | 500 |
| `from_year` | целое 1900…2030 | 1970 |
| `min_votes` | целое 0…100 000 | 100 |
| `resume` | логическое | `False` |

Возврат — отчёт: `{load_id, status, pages_done, movies_upserted, movies_skipped, last_page, duration_s}`. Алгоритм, запросы и обработка ошибок — §7; параметры командной строки — [110](110.ui-ux.md).

## 5. Поиск кандидатов: значения, которые задаёт модуль

| Значение | Величина | Где используется | Почему |
|---|---|---|---|
| Порог голосов | `vote_count >= 100` | всегда в `find_movies`; по умолчанию в загрузке (`--min-votes 100`) | фильм с 9,5 и 12 голосами не должен попадать в подборку (US-16) |
| Обязательный рейтинг | `rating IS NOT NULL` | `find_movies` | без рейтинга нечем сортировать |
| Число карточек по умолчанию | 15 | `limit` | агенту нужно 3 и запас на ослабление критериев |
| Максимум карточек | 30 | `limit` | ограничение контекста модели |
| Объём каталога MVP | до 10 000 фильмов | загрузка, 500 страниц × 20 | предел пагинации TMDB — 500 страниц |

Порог 100 — единственное число в проекте: оно же значение по умолчанию `--min-votes`, оно же фильтр выдачи. Менять его можно только вместе с NFR-DB-12, US-16 и TS-DB-04.

`find_movies` к TMDB не обращается: соответствие «параметр инструмента → SQL» — в таблице [§4.4](130.api-contracts.md#44-find_movies). Параметры TMDB есть только у загрузки каталога ([§7.1](130.api-contracts.md#71-запросы-к-tmdb)).

## 6. Ошибки

| Ситуация | Исключение | Код | Кто видит |
|---|---|---|---|
| Параметр вне диапазона, неверный тип | `ToolError` | `INVALID_PARAM` | модель; пользователю не показывается |
| Жанр не найден в справочнике | `ToolError` | `UNKNOWN_GENRE` | модель; пользователю не показывается |
| Фильм или выбор отсутствует | `ToolError` | `NOT_FOUND` | модель; пользователю не показывается |
| Город не найден | `ServiceError` | `CITY_NOT_FOUND` | пользователь, текст из contracts §6 |
| Каталог пуст | `ServiceError` | `CATALOG_EMPTY` | пользователь, текст из contracts §6 |
| SQLite недоступна, `database is locked` после 5 с, ошибка диска | `ServiceError` | `DATA_UNAVAILABLE` | пользователь, текст из contracts §6 |
| TMDB 401 при загрузке | `IngestError` | — | сопровождающий (stderr, exit code 2); в журнал `event=ingest_error code=TMDB_UNAUTHORIZED` |
| TMDB недоступен после повторов | `IngestError` | — | сопровождающий (stderr, exit code 4) |

Правила:

1. `ToolError` сериализуется в результат инструмента: `{"error": {"code": "UNKNOWN_GENRE", "message": "…"}}`. Это не `AgentResponse` и не HTTP-ошибка.
2. `ServiceError` перехватывает оркестратор и превращает в `AgentResponse(type="error", error_code=…)` с дословным текстом из [contracts §6](../overall/contracts.md#6-ошибки); API-слой добавляет HTTP-статус из той же таблицы.
3. `IngestError` — только для скрипта загрузки; пользователь его не видит.
4. Новых кодов ошибок модуль не заводит ([ADR-035](../agents/145.architecture-decisions.md)); отсутствие подходящего кода — повод для ADR, а не для «своего» текста.

Пример ответа инструмента:

```json
{"error": {"code": "UNKNOWN_GENRE",
           "message": "Жанр «киберпанк» отсутствует. Допустимые: боевик, комедия, драма, ужасы, фантастика, …"}}
```

Список допустимых жанров в сообщении — первые 20 названий из `genres` по `tmdb_id`, чтобы ответ не превышал разумный размер контекста.

## 7. Загрузка каталога

### 7.1. Запросы к TMDB

Базовый адрес — `https://api.themoviedb.org/3`, ключ — параметр `api_key` из `TMDB_API_KEY` ([config.md](../overall/config.md#1-переменные-окружения)), заголовок `Accept: application/json`, `language=ru-RU` во всех запросах.

| Шаг | Запрос | Параметры | Что берём |
|---|---|---|---|
| 1. Жанры | `GET /genre/movie/list` | `language=ru-RU` | `genres[]`: `id`, `name` → upsert в `genres` |
| 2. Страница каталога | `GET /discover/movie` | `language=ru-RU`, `sort_by=popularity.desc`, `vote_count.gte={min_votes}`, `primary_release_date.gte={from_year}-01-01`, `include_adult=false`, `page=N` | `results[]`: `id`, `title`, `original_title`, `release_date`, `vote_average`, `vote_count`, `popularity`, `poster_path`, `genre_ids`, `adult`, `overview` |
| 3. Детали фильма | `GET /movie/{id}` | `language=ru-RU`, `append_to_response=credits,release_dates` | `runtime`, `overview`, `genres[]`, `credits.cast[0:10]`, `release_dates.results[]` |

Правила:

1. `discover` отдаёт 20 фильмов на страницу, `page` — 1…500; 500 — предел TMDB, поэтому объём каталога 10 000 фильмов.
2. Детали запрашиваются для каждого фильма: в `discover` нет `runtime`, актёров и сертификатов.
3. `include_adult=false` — взрослый контент в каталог не попадает; столбец `movies.adult` остаётся для полноты и равен 0.
4. `region` в `discover` не передаётся: каталог общий, город влияет только на погоду.
5. `genre_ids` из `discover` не используются — жанры берутся из `movie/{id}.genres[]` с русскими названиями; `genre_ids` нужны только для сверки.

### 7.2. Нормализация

| Поле базы | Правило |
|---|---|
| `movies.tmdb_id` | `id` из TMDB |
| `movies.title` | `title`, если пусто — `original_title`, если пусто — `«Без названия»` |
| `movies.title_norm` | `normalize_text(title)` |
| `movies.year` | первые 4 символа `release_date`; пустая дата — `NULL` |
| `movies.runtime` | `runtime` из деталей; `0` — `NULL` |
| `movies.rating` | `vote_average`; `0` при `vote_count = 0` — `NULL` |
| `movies.vote_count` | `vote_count` |
| `movies.age_rating` | по [ADR-018](145.architecture-decisions.md#adr-018) |
| `movies.overview` | `overview`; пустая строка — `NULL` |
| `movies.poster_path` | `poster_path` как есть (`/abc.jpg`) |
| `genres` | `movie/{id}.genres[]`; неизвестный `tmdb_id` — пропуск жанра с записью в журнал |
| `movie_cast` | первые 10 элементов `credits.cast`; `billing_order` — индекс в массиве; `character` — `character` |

Фильм без `id` или с пустым `title` и `original_title` пропускается и считается в `movies_skipped`. Фильм, у которого после деталей нет ни одного жанра, сохраняется — жанровый фильтр его просто не найдёт.

### 7.3. Транзакции и порции

1. Порция — одна страница `discover` (до 20 фильмов). После загрузки деталей страницы открывается одна транзакция: upsert `movies`, замена `movie_genres`, upsert `people`, замена `movie_cast`.
2. После коммита обновляются `catalog_loads.last_page = N`, `movies_upserted`, `movies_skipped`. Прерывание между коммитами теряет не больше одной страницы, а `last_page` всегда указывает на полностью зафиксированную страницу.
3. Страница из 20 фильмов даёт ≈ 480 строк изменений (`movies` + жанры + актёры) — NFR-DB-03 выполняется одной транзакцией.
4. Upsert — `INSERT … ON CONFLICT(tmdb_id) DO UPDATE`. `movies.id` не меняется, поэтому оценки и выборы переживают перезагрузку каталога.
5. `updated_at` обновляется у каждого upsert-нутого фильма.

### 7.4. Ограничение частоты и повторы

| Параметр | Значение |
|---|---|
| Темп | не больше 40 запросов/с; пауза между запросами ≥ 25 мс |
| Параллельность | 1 поток: последовательные запросы, предсказуемый темп |
| Тайм-аут запроса | 10 с |
| Ответ 429 | пауза из `Retry-After` (секунды), иначе 1, 2, 4, 8, 16 с; до 5 повторов |
| Ответ 5xx или тайм-аут | тот же ряд пауз, до 5 повторов |
| Ответ 404 на детали | фильм пропускается, `movies_skipped += 1` |
| Ответ 401 | остановка, `status = failed`, `IngestError` |

После пяти неудачных повторов по одной странице загрузка останавливается: `status = partial`, `IngestError`, отчёт содержит достигнутую страницу.

### 7.5. Возобновление и отчёт

1. `--resume` находит последнюю запись `catalog_loads` со `status IN ('running','partial')` и параметрами, совпадающими с текущими; продолжает с `last_page + 1`.
2. Если подходящей записи нет, создаётся новая (`running`, `last_page = 0`), загрузка идёт с первой страницы.
3. `Ctrl+C` — обработка `KeyboardInterrupt`: текущая порция коммитится, `status = partial`, `finished_at = now`, отчёт печатается, exit code 1.
4. Успех — `status = completed`, exit code 0. Отчёт: `load_id`, страницы, `upserted`, `skipped`, длительность.
5. Запись `catalog_loads` не удаляется: по ней строится история загрузок.

## 8. Погода и геокодирование

### 8.1. Запросы к Open-Meteo

| Шаг | Запрос | Параметры | Что берём |
|---|---|---|---|
| Геокодирование | `GET https://geocoding-api.open-meteo.com/v1/search` | `name={query}`, `count=5`, `language=ru`, `format=json` | `results[]`: `name`, `admin1`, `country`, `latitude`, `longitude` |
| Погода | `GET https://api.open-meteo.com/v1/forecast` | `latitude`, `longitude`, `current=temperature_2m,weather_code,is_day`, `timezone=auto` | `current.temperature_2m`, `current.weather_code`, `current.is_day` |

Ключ не нужен. Тайм-аут — 3 с (NFR-DB-04); повторов нет — погода не должна задерживать ход.

### 8.2. Структура `Weather`

| Поле | Тип | Значение |
|---|---|---|
| `city` | string | `users.city`; город не переопределяется |
| `condition` | string | `clear`, `cloudy`, `fog`, `drizzle`, `rain`, `snow`, `thunderstorm`, `unknown` |
| `temp_c` | float | `current.temperature_2m`, округление до 1 знака |
| `is_day` | bool | `current.is_day == 1` |

`condition` — закрытый перечень: английский код, русскую формулировку выбирает агент. Новое значение — изменение контракта этого документа. Влияние на подбор — подсказка тона, а не фильтр: дождь и холод склоняют к спокойному кино, но не отсекают фильмы ([ADR-036](../agents/145.architecture-decisions.md), [120 агентов §2](../agents/120.data-model.md#2-правила-контекст--критерии-поиска)).

### 8.3. Коды WMO → `condition`

| Код `weather_code` | `condition` |
|---|---|
| 0, 1 | `clear` |
| 2, 3 | `cloudy` |
| 45, 48 | `fog` |
| 51, 53, 55, 56, 57 | `drizzle` |
| 61, 63, 65, 66, 67, 80, 81, 82 | `rain` |
| 71, 73, 75, 77, 85, 86 | `snow` |
| 95, 96, 99 | `thunderstorm` |
| прочие | `unknown` |

### 8.4. Кэш и отказ

| Что | Правило |
|---|---|
| Ключ кэша погоды | `(latitude, longitude)`, округлённые до 3 знаков |
| TTL погоды | 30 минут; по истечении — новый запрос |
| Размер кэша | до 1 000 записей, вытеснение по давности использования |
| Отрицательный кэш | не ведётся: отказ не запоминается, следующий вызов пробует снова |
| Кэш геокодирования | ключ — нормализованный запрос, TTL 24 ч, до 500 записей |
| Отказ сервиса | `None`, запись в журнал `event=weather_unavailable` без координат и города |
| Нет города | `None` без запроса |

Кэш живёт в памяти процесса: перезапуск backend его очищает. Общий кэш между процессами не нужен — один backend.

## 9. Справочник жанров

1. `genres` — единственный источник допустимых названий. Модель получает их из результата `find_movies` и из списка в ответе `UNKNOWN_GENRE`.
2. Сопоставление — по `name_norm`; `name` возвращается в `MovieCard.genres`.
3. Жанр, которого нет в справочнике, не передаётся в `find_movies`: агент опускает его и ищет по остальным критериям ([120 агентов §2](../agents/120.data-model.md#2-правила-контекст--критерии-поиска)).
4. Справочник обновляется при каждом запуске загрузки; удаление жанра из TMDB не удаляет строку (на неё ссылаются фильмы) — жанр просто перестаёт попадать в новые фильмы.
