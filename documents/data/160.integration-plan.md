# 160 — Integration Plan

*CineMatch. Модуль данных* | [оглавление модуля](README.md)

Сроки согласованы с [дорожной картой](../../docs/roadmap.md); критерий каждой строки проверяем без обращения к авторам.

| № | Интеграция | С кем | Срок | Критерий готовности |
|---|---|---|---|---|
| 1 | Общие структуры, конфигурация, сборка (`contracts.md`, `config.md`, `build.md`) | все модули | 11.11 | `MovieCard`, коды ошибок и переменные зафиксированы; pull request одобрен всеми тремя |
| 2 | Ключ TMDB и пробные запросы | TMDB | 09.11 | `genre/movie/list` и `movie/{id}` отвечают на `ru-RU`; ключ в `.env`, не в git |
| 3 | Схема, первая миграция, фикстура тестов | модуль данных | 12.11 | `alembic upgrade head` и `downgrade -1` проходят; TS-DB-10 |
| 4 | Скрипт загрузки, каталог 10 000 фильмов | TMDB | 15.11 | TS-DB-01…03, TS-DB-11; отчёт и коды завершения |
| 5 | Поиск, профиль, оценки, выборы, история | модуль агентов | 19.11 | TS-DB-04…06 |
| 6 | Погода и геокодирование | Open-Meteo | 19.11 | TS-DB-07 |
| 7 | Удаление данных, сессии, одновременная работа | модуль интерфейса | 22.11 | TS-DB-08, TS-DB-09 |
| 8 | Демо MVP | все | 29.11 | сквозной сценарий в Docker Compose на реальных данных |

Правила:

1. Интеграция считается закрытой только при пройденном сценарии из колонки «критерий»; «код написан» — не критерий.
2. Пункты 3–7 идут после пункта 1: контракты и конфигурация — источник значений для остальных.
3. Пункт 2 можно выполнять параллельно: ключ нужен только загрузке, backend стартует без сети.
4. Изменение сроков фиксируется в дорожной карте, а не только здесь.

### Будущий функционал

Таблицы и функции напоминаний, подписок, новинок; интеграция с планировщиком.
