# 120 — Data Model

*CineMatch. Модуль данных* | [оглавление модуля](README.md)

Документ описывает физическую модель SQLite: таблицы, столбцы, ограничения, индексы, правила заполнения из TMDB и миграции. Логическая модель — на диаграмме выше; структуры, которые модуль отдаёт наружу (`MovieCard`, `RecommendedMovie`), определены в [общем контракте](../overall/contracts.md#2-модели) и здесь не дублируются.

![Логическая модель данных](diagrams/120-er.svg)

Что модуль хранит и кто это читает — [070](070.role-matrix.md); как заполняется каталог — [130 §7](130.api-contracts.md#7-загрузка-каталога) и [146](146.logic-scheme.md).

## 1. Файл базы и параметры подключения

| Параметр | Значение | Почему так |
|---|---|---|
| Файл | `cinematch.db`; в контейнере `/data/cinematch.db`, локально `storage/cinematch.db` ([config.md](../overall/config.md#1-переменные-окружения)) | один файл, бэкап копированием ([ADR-011](145.architecture-decisions.md#adr-011)) |
| Драйвер | SQLAlchemy 2.0, диалект `sqlite`, драйвер `pysqlite` | [ADR-029](145.architecture-decisions.md#adr-029) |
| `PRAGMA foreign_keys` | `ON` — на каждом соединении | каскадное удаление данных пользователя ([ADR-016](145.architecture-decisions.md#adr-016)) |
| `PRAGMA journal_mode` | `WAL` | чтение во время загрузки каталога |
| `PRAGMA busy_timeout` | `5000` (мс) | ожидание блокировки вместо мгновенной ошибки |
| `PRAGMA synchronous` | `NORMAL` | достаточная надёжность при WAL и скорость записи |
| `PRAGMA temp_store` | `MEMORY` | сортировка выдачи не пишет на диск |
| Даты | TEXT, ISO 8601 в UTC: `2026-11-08T18:15:00Z` | сравнимы как строки, читаемы в SQLite CLI |
| Часовой пояс | все значения в UTC; пояс пользователя в базу не попадает | одна шкала для `expires_at` и `rated_at` |

Правила:

1. Параметры задаются один раз в `cinematch/data/db.py` в обработчике события `connect` SQLAlchemy; в запросах `PRAGMA` не повторяются.
2. `foreign_keys` в SQLite по умолчанию выключены — без явного `ON` каскад не работает, и `delete_user_data` оставит «сирот».
3. Один процесс пишет, много читают. Загрузка каталога и backend работают одновременно: писатель ждёт до 5 с, затем получает `database is locked` (`DATA_UNAVAILABLE`).
4. Файл базы не коммитится; каталог `storage/` в `.gitignore`.

## 2. Схема

Схема создаётся первой миграцией Alembic `0001_initial.py`; всё ниже — её содержимое. Изменение схемы — только новой ревизией (§9).

```sql
-- справочник жанров TMDB
CREATE TABLE genres (
    id       INTEGER PRIMARY KEY AUTOINCREMENT,
    tmdb_id  INTEGER NOT NULL UNIQUE,
    name     TEXT    NOT NULL UNIQUE,          -- русское название из TMDB
    name_norm TEXT   NOT NULL UNIQUE           -- lower(), ё → е, сжатые пробелы
);

-- каталог фильмов
CREATE TABLE movies (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    tmdb_id        INTEGER NOT NULL UNIQUE,
    title          TEXT    NOT NULL,           -- русское, затем original_title, затем «Без названия»
    title_norm     TEXT    NOT NULL,           -- lower(), ё → е, сжатые пробелы; для search_movie
    original_title TEXT,
    year           INTEGER,
    runtime        INTEGER,                    -- минуты
    rating         REAL,                       -- TMDB vote_average
    vote_count     INTEGER NOT NULL DEFAULT 0,
    popularity     REAL,
    age_rating     TEXT,                       -- '0+','6+','12+','16+','18+' или NULL
    overview       TEXT,                       -- описание на русском
    poster_path    TEXT,                       -- '/abc.jpg'; NULL — постера нет
    adult          INTEGER NOT NULL DEFAULT 0, -- флаг TMDB adult
    updated_at     TEXT    NOT NULL,           -- время последнего upsert
    CHECK (runtime IS NULL OR runtime > 0),
    CHECK (rating  IS NULL OR rating BETWEEN 0 AND 10),
    CHECK (vote_count >= 0),
    CHECK (age_rating IS NULL OR age_rating IN ('0+','6+','12+','16+','18+')),
    CHECK (adult IN (0, 1))
);

CREATE TABLE movie_genres (
    movie_id INTEGER NOT NULL REFERENCES movies(id) ON DELETE CASCADE,
    genre_id INTEGER NOT NULL REFERENCES genres(id) ON DELETE RESTRICT,
    PRIMARY KEY (movie_id, genre_id)
);

CREATE TABLE people (
    id      INTEGER PRIMARY KEY AUTOINCREMENT,
    tmdb_id INTEGER NOT NULL UNIQUE,
    name    TEXT    NOT NULL
);

CREATE TABLE movie_cast (
    movie_id      INTEGER NOT NULL REFERENCES movies(id)  ON DELETE CASCADE,
    person_id     INTEGER NOT NULL REFERENCES people(id)  ON DELETE RESTRICT,
    billing_order INTEGER NOT NULL,            -- 0…9, порядок TMDB cast
    character     TEXT,
    PRIMARY KEY (movie_id, person_id),
    CHECK (billing_order BETWEEN 0 AND 9)
);

CREATE TABLE users (
    user_id    TEXT PRIMARY KEY,               -- 'web:local' в MVP
    source     TEXT NOT NULL,                  -- 'web'
    consent_at TEXT,
    city       TEXT,
    latitude   REAL,
    longitude  REAL,
    created_at TEXT NOT NULL,
    CHECK (source IN ('web')),
    CHECK (latitude  IS NULL OR latitude  BETWEEN -90 AND 90),
    CHECK (longitude IS NULL OR longitude BETWEEN -180 AND 180)
);

CREATE TABLE user_ratings (
    user_id    TEXT    NOT NULL REFERENCES users(user_id)  ON DELETE CASCADE,
    movie_id   INTEGER NOT NULL REFERENCES movies(id)      ON DELETE CASCADE,
    rating     INTEGER NOT NULL,
    mood_match TEXT,
    source     TEXT    NOT NULL,
    rated_at   TEXT    NOT NULL,
    PRIMARY KEY (user_id, movie_id),
    CHECK (rating BETWEEN 1 AND 10),
    CHECK (mood_match IS NULL OR mood_match IN ('yes','partly','no')),
    CHECK (source IN ('after_choice','manual'))
);

CREATE TABLE user_choices (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id   TEXT    NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    movie_id  INTEGER NOT NULL REFERENCES movies(id)     ON DELETE CASCADE,
    status    TEXT    NOT NULL,
    chosen_at TEXT    NOT NULL,
    closed_at TEXT,
    CHECK (status IN ('pending','rated','dismissed'))
);

CREATE TABLE sessions (
    user_id    TEXT PRIMARY KEY REFERENCES users(user_id) ON DELETE CASCADE,
    state_json TEXT NOT NULL,                  -- SessionState, см. §7
    expires_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);

CREATE TABLE catalog_loads (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    started_at      TEXT NOT NULL,
    finished_at     TEXT,
    status          TEXT NOT NULL,
    params_json     TEXT NOT NULL,             -- {"pages":…,"from_year":…,"min_votes":…}
    movies_upserted INTEGER NOT NULL DEFAULT 0,
    movies_skipped  INTEGER NOT NULL DEFAULT 0,
    last_page       INTEGER NOT NULL DEFAULT 0,
    CHECK (status IN ('running','completed','partial','failed')),
    CHECK (last_page >= 0)
);

CREATE INDEX ix_movies_rating ON movies(rating DESC, vote_count DESC, id)
    WHERE rating IS NOT NULL;
CREATE INDEX ix_movies_year       ON movies(year);
CREATE INDEX ix_movies_title_norm ON movies(title_norm);
CREATE INDEX ix_movie_genres_genre ON movie_genres(genre_id, movie_id);
CREATE INDEX ix_movie_cast_movie   ON movie_cast(movie_id, billing_order);
CREATE INDEX ix_movie_cast_person  ON movie_cast(person_id, movie_id);
CREATE INDEX ix_user_ratings_date  ON user_ratings(user_id, rated_at DESC);
CREATE INDEX ix_user_choices_user  ON user_choices(user_id, chosen_at DESC);
CREATE UNIQUE INDEX ux_user_choices_pending ON user_choices(user_id)
    WHERE status = 'pending';
CREATE INDEX ix_sessions_expires   ON sessions(expires_at);
CREATE INDEX ix_catalog_loads_state ON catalog_loads(status, started_at DESC);
```

## 3. `movies`

| Столбец | Тип | Ограничение | Источник TMDB | Описание |
|---|---|---|---|---|
| `id` | INTEGER | PK | — | внутренний ключ; на него ссылаются `MovieCard.movie_id`, оценки и выборы |
| `tmdb_id` | INTEGER | NOT NULL UNIQUE | `id` | ключ идемпотентности загрузки |
| `title` | TEXT | NOT NULL | `title` (`language=ru-RU`), иначе `original_title`, иначе `«Без названия»` | правило — [contracts §2.1](../overall/contracts.md#21-moviecard--карточка-фильма-из-каталога) |
| `title_norm` | TEXT | NOT NULL | вычисляется из `title` | поиск без учёта регистра и «ё» |
| `original_title` | TEXT | — | `original_title` | |
| `year` | INTEGER | — | первые 4 символа `release_date` | пустая дата → NULL |
| `runtime` | INTEGER | > 0 или NULL | `runtime` (только из `movie/{id}`) | в `discover` длительности нет |
| `rating` | REAL | 0–10 или NULL | `vote_average` | `0.0` при отсутствии голосов → NULL |
| `vote_count` | INTEGER | ≥ 0, по умолчанию 0 | `vote_count` | порог выдачи — [130 §5](130.api-contracts.md#5-поиск-кандидатов-значения-которые-задаёт-модуль) |
| `popularity` | REAL | — | `popularity` | порядок загрузки; в выдаче не участвует |
| `age_rating` | TEXT | `0+`…`18+` или NULL | `release_dates` | правило — [ADR-018](145.architecture-decisions.md#adr-018) |
| `overview` | TEXT | — | `overview` (`language=ru-RU`) | для `get_movie_with_credits` |
| `poster_path` | TEXT | — | `poster_path` | `NULL` — постера нет |
| `adult` | INTEGER | 0/1 | `adult` | признак взрослого контента |
| `updated_at` | TEXT | NOT NULL | — | момент upsert |

`MovieCard.poster_url` собирается при чтении: `poster_path` пуст → `null`, иначе `https://image.tmdb.org/t/p/w342{poster_path}`. В базе хранится только путь: базовый адрес — конфигурация отображения, а не данные.

`MovieCard.rating` и `vote_count` отдаются как есть (`null` и `0`); отбор по порогу голосов уже выполнен в `find_movies` (§5 130), поэтому в карточке порог не виден.

## 4. `genres`, `movie_genres`, `people`, `movie_cast`

| Таблица | Столбцы | Правила |
|---|---|---|
| `genres` | `id`, `tmdb_id`, `name`, `name_norm` | загружается целиком при каждом запуске загрузки (`GET /3/genre/movie/list?language=ru-RU`); `name` — как в TMDB, `name_norm` — для поиска жанра по словам модели |
| `movie_genres` | `movie_id`, `genre_id` | при upsert фильма набор заменяется целиком: `DELETE` + `INSERT` в той же транзакции |
| `people` | `id`, `tmdb_id`, `name` | upsert по `tmdb_id`; один человек встречается во многих фильмах |
| `movie_cast` | `movie_id`, `person_id`, `billing_order`, `character` | только первые 10 актёров `credits.cast`; `billing_order` — индекс в массиве (0…9); при upsert фильма заменяется целиком; если человек встречается в `cast` дважды, остаётся первое вхождение |

Порядок жанров в `MovieCard.genres` — по возрастанию `genres.tmdb_id` (порядок справочника TMDB), а не в порядке ответа `movie/{id}`: одна и та же карточка должна выглядеть одинаково в подборке и в истории.

Нормализация строк (`name_norm`, `title_norm`): `lower()`, замена `ё` на `е`, удаление повторных пробелов, обрезка. Функция — `cinematch/data/models.py::normalize_text`. Нужна потому, что `LIKE` и `lower()` в SQLite не понимают кириллицу.

## 5. `users`, `user_ratings`, `user_choices`

| Таблица | Столбцы | Правила |
|---|---|---|
| `users` | `user_id`, `source`, `consent_at`, `city`, `latitude`, `longitude`, `created_at` | `user_id` с префиксом источника ([ADR-017](145.architecture-decisions.md#adr-017)); `consent_at` — момент согласия, `NULL` — согласия нет; город и координаты заполняются вместе |
| `user_ratings` | `user_id`, `movie_id`, `rating`, `mood_match`, `source`, `rated_at` | одна оценка на пару; повторная оценка перезаписывает `rating`, `mood_match`, `source`, `rated_at` |
| `user_choices` | `id`, `user_id`, `movie_id`, `status`, `chosen_at`, `closed_at` | не более одного `pending` на пользователя — частичный уникальный индекс; `rated` ставит `save_rating`, `dismissed` — `save_choice` (новый выбор) или `close_choice` |

`mood_match` — попадание фильма в настроение: `yes`, `partly`, `no` или `NULL`. `source` оценки: `after_choice` (оценка после выбора) или `manual` (отметка «посмотрел X, на 7 из 10»).

`city` хранится как `name` выбранного варианта `resolve_city` (например, `Москва`); `region` и `country` в базу не пишутся — они нужны только для выбора варианта пользователем.

## 6. `sessions`

| Столбец | Тип | Правила |
|---|---|---|
| `user_id` | TEXT PK → `users` `ON DELETE CASCADE` | одна сессия на пользователя |
| `state_json` | TEXT NOT NULL | JSON структуры `SessionState` ([contracts §2.5](../overall/contracts.md#25-sessionstate--состояние-диалога)); правила заполнения — [120 агентов](../agents/120.data-model.md#3-сессия-и-восстановление) |
| `expires_at` | TEXT NOT NULL | `now + 24 часа`; каждое сохранение продлевает |
| `updated_at` | TEXT NOT NULL | момент последней записи |

Правила:

1. Модуль данных не интерпретирует `state_json`: принимает `SessionState`, сериализует `model_dump_json()`, возвращает `SessionState.model_validate_json()`. Схему полей ведёт модуль агентов.
2. Чтение просроченной сессии (`expires_at <= now`) удаляет строку и возвращает `None`.
3. Повреждённый JSON (ручная правка, сбой записи) — запись в журнал `event=error code=DATA_UNAVAILABLE layer=data`, строка удаляется, возвращается `None`: сессия восстанавливается заново по правилу [120 агентов §3](../agents/120.data-model.md#3-сессия-и-восстановление). Ход диалога не прерывается.
4. `purge_expired()` удаляет все строки с `expires_at <= now` одной транзакцией и возвращает число удалённых.
5. Сессия не создаётся до согласия: на этапе `consent` строки `users` ещё нет, внешний ключ не даст записать сессию. Этап в этом случае выводится из `get_user`, а `save_session_state` не вызывается ([120 агентов §3](../agents/120.data-model.md#3-сессия-и-восстановление)).

## 7. `catalog_loads`

Журнал запусков загрузки: по нему восстанавливается прерванный запуск и строится отчёт.

| Столбец | Правила |
|---|---|
| `status` | `running` при старте; `completed` — все страницы; `partial` — прерывание; `failed` — 401 или ошибка базы |
| `params_json` | параметры запуска: `pages`, `from_year`, `min_votes`; по ним `--resume` отличает чужой запуск |
| `last_page` | последняя **зафиксированная** страница; обновляется после коммита порции |
| `movies_upserted`, `movies_skipped` | счётчики для отчёта; `skipped` — ответы 404 и фильмы без обязательных полей |
| `finished_at` | заполняется при любом терминальном статусе |

## 8. Соответствие контрактам

| Что отдаётся наружу | Откуда берётся | Документ |
|---|---|---|
| `MovieCard` | `movies` + `genres` через `movie_genres` | [contracts §2.1](../overall/contracts.md#21-moviecard--карточка-фильма-из-каталога) |
| `MovieDetails` (`MovieCard` + `actors`, `overview`) | `movies`, `people` через `movie_cast` | [130 §4](130.api-contracts.md#4-описание-функций) |
| `EveningContext`, `SessionState` | не хранятся в столбцах; `SessionState` — в `sessions.state_json` | [contracts §2.4–2.5](../overall/contracts.md#24-eveningcontext--контекст-вечера) |
| `AgentTrace` | не хранится | [contracts §2.7](../overall/contracts.md#27-agenttrace--шаг-трассы) |
| `reason` в `RecommendedMovie` | не хранится: формирует агент | [contracts §2.2](../overall/contracts.md#22-recommendedmovie--карточка-в-подборке) |
| Коды ошибок | не хранятся | [contracts §6](../overall/contracts.md#6-ошибки) |

Полей «объяснение», «причина», «рекомендация» в схеме нет: рекомендация — свойство хода диалога, а не каталога.

## 9. Миграции

| Правило | Значение |
|---|---|
| Инструмент | Alembic; каталог `migrations/`, версии `migrations/versions/` |
| Первая ревизия | `0001_initial.py` — схема §2 |
| Запуск | `alembic upgrade head` при старте backend ([build.md §3](../overall/build.md#3-порядок-старта-backend)) и вручную перед загрузкой каталога |
| Изменение схемы | только новой ревизией с осмысленным именем (`0002_add_series.py`); правка существующей ревизии запрещена |
| Версия схемы | таблица `alembic_version`; в документах не дублируется |
| Совместимость с PostgreSQL | типы и запросы — через SQLAlchemy Core/ORM без `sqlite3`-специфичного SQL, кроме `PRAGMA` в `db.py` ([ADR-029](145.architecture-decisions.md#adr-029)) |
| Откат | `alembic downgrade -1` обязателен для каждой ревизии до MVP |

## 10. Хранение и удаление

| Данные | Срок | Механизм |
|---|---|---|
| Каталог | бессрочно, обновляется загрузкой | upsert по `tmdb_id`; старые записи не удаляются |
| Сессии | 24 часа без активности | `expires_at`, `purge_expired()` при старте |
| Оценки, выборы, настройки | до удаления пользователем | `ON DELETE CASCADE` от `users` |
| Журнал загрузок | бессрочно | `catalog_loads` |

`delete_user_data(user_id)` в одной транзакции считает строки в `user_ratings`, `user_choices`, `sessions`, затем удаляет строку `users`; каскад удаляет остальное. Каталог, `genres`, `people`, `movie_cast`, `catalog_loads` не затрагиваются. Возврат — `{deleted_counts: {user_ratings, user_choices, sessions, users}}`; порядок ключей фиксирован.

### Будущий функционал

Таблицы `reminders`, `subscriptions`; сериалы (`series`, `episodes`); переход на PostgreSQL при развёртывании для многих пользователей.
