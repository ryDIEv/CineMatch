# 080 — User Stories

*CineMatch. Модуль данных* | [оглавление модуля](README.md)

Нумерация сквозная: US-13…US-16 принадлежат модулю данных, остальные — [модулю агентов](../agents/080.user-stories.md) и [модулю интерфейса](../ui/080.user-stories.md). Истории, где модуль участвует, но владелец другой, здесь не повторяются.

**US-13.** Как сопровождающий, я хочу загрузить каталог одной командой, чтобы подготовить приложение к работе. *(UC-9)*

- Given `TMDB_API_KEY` задан и контейнеры собраны, When выполняется `docker compose run --rm backend python -m scripts.load_catalog`, Then в базе до 10 000 фильмов с жанрами, актёрами, постерами и возрастной маркировкой; в конце — отчёт с числом загруженных, пропущенных и страниц; exit code 0.
- Given полный запуск на 500 страниц, When он завершён, Then время ≤ 20 мин (NFR-DB-15), файл базы ≤ 100 МБ (NFR-DB-16).
- Given ключ неверный, When запускается загрузка, Then она останавливается на первом ответе 401 с сообщением «Ключ TMDB не принят (401). Проверьте TMDB_API_KEY.», статус `failed`, exit code 2.
- Given каталог уже загружен, When загрузка запускается снова, Then записи обновляются по `tmdb_id`, `movies.id` не меняется, оценки и выборы пользователей сохраняются.

**US-14.** Как пользователь, я не хочу получать в подборке фильмы, которые уже оценил. *(UC-3)*

- Given фильм оценён пользователем, When агент вызывает `find_movies`, Then фильм не возвращается ни при каких критериях.
- Given фильм показан в этой сессии, но не оценён, When агент просит другие варианты, Then фильм исключается через `exclude_ids`, но остаётся доступным в истории.

**US-15.** Как сопровождающий, я хочу безопасно перезапускать загрузку, чтобы обновлять каталог и продолжать прерванную. *(UC-9)*

- Given загрузка прервана на странице 20, When она запущена с `--resume`, Then продолжается со страницы 21, дублей нет.
- Given фильм уже в каталоге, When он загружается повторно, Then запись обновляется без дубликата, `updated_at` меняется.
- Given загрузка прервана между коммитами страниц, When она продолжается, Then теряется не больше одной страницы (≤ 20 фильмов).

**US-16.** Как пользователь, я хочу, чтобы в подборку не попадали малоизвестные фильмы со случайно высоким рейтингом. *(UC-3)*

- Given фильм с рейтингом 9,5 и 12 голосами, When выполняется `find_movies`, Then фильм не возвращается (порог 100 голосов, NFR-DB-12).
- Given фильм с рейтингом 8,0 и 1 500 голосами, When он подходит по остальным критериям, Then он может попасть в выдачу.
- Given каталог загружен с `--min-votes 100`, When пользователь просит любые фильмы, Then порог действует и в SQL, и после загрузки — отключить его модель не может.
