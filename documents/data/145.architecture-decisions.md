# 145 — ADR

*CineMatch. Модуль данных* | [оглавление модуля](README.md)

Нумерация сквозная; ADR-001…ADR-010 — [модуль агентов](../agents/145.architecture-decisions.md).

**ADR-011. SQLite, один файл, режим WAL.** *Принято.* Контекст: один пользователь, локальный запуск, команда без опыта администрирования СУБД. Решение: SQLite в томе Docker, WAL, внешние ключи. Последствия: (+) нет отдельного сервера базы, простое резервное копирование, достаточная скорость; (−) одна запись в момент времени; для многих пользователей потребуется PostgreSQL.

**ADR-012. Каталог — TMDB API.** *Принято.* Контекст: Кинопоиск и Netflix не дают открытого API; нужны жанры, актёры, постеры, данные на русском. Решение: TMDB с бесплатным ключом, соблюдение условий и атрибуции. Последствия: (+) полные данные и постеры; (−) регистрация ключа, зависимость от TMDB.

**ADR-013. Профиль рассчитывается при чтении.** *Принято.* Решение: отдельной таблицы профиля нет; вес жанра — среднее (`rating` − 5,5) / 4,5 по оценённым фильмам жанра с учётом числа оценок; аналогично для актёров. Последствия: (+) нет рассинхронизации; (−) расчёт при каждом запросе — допустимо при сотнях оценок.

**ADR-014. Погода — Open-Meteo с кэшем 30 минут.** *Принято.* Решение: координаты города сохраняются при онбординге, погода кэшируется в памяти. Последствия: (+) бесплатно, без регистрации; (−) только некоммерческое использование.

**ADR-015. Проверка параметров инструментов в модуле данных.** *Принято.* Решение: проверка типов и диапазонов, понятная ошибка для модели, SQL только с подстановкой параметров. Последствия: (+) защита от ошибок модели и внедрения SQL.

**ADR-016. Удаление через каскадные внешние ключи.** *Принято.* Последствия: (+) полное удаление одним запросом, ни одна таблица не забыта; (−) внешние ключи нужно включать для каждого подключения.

**ADR-017. Идентификатор пользователя с префиксом источника.** *Принято.* Решение: `web:local` в MVP; в будущем `web:<id>`, `tg:<id>`. Последствия: (+) готовность к нескольким пользователям и интерфейсам без изменения схемы.

**ADR-018. Возрастная маркировка из TMDB `release_dates`.** *Предложено.* Решение: маркировка для `RU`; при отсутствии — преобразование `US` (G → 0+, PG → 6+, PG-13 → 12+, R → 16+, NC-17 → 18+); при флаге `adult` — 18+. Последствия: (+) маркировка у большинства фильмов; (−) преобразование приблизительное.
