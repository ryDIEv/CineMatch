# TS-AG — сценарии модуля ИИ-агентов

Каждый сценарий выполняется на фикстуре каталога и тестовом двойнике LLM. Для сценариев с реальной моделью (TS-AG-09) используется `model-eval.md`.

| ID | Шаги | Вход | Ожидаемый результат | Способ проверки |
|---|---|---|---|---|
| TS-AG-01 | Открыть сессию; отправить `/start`; принять согласие кнопкой; назвать город; повторить на чистой базе с текстовым согласием | `/start`, `POST /consent`, «Москва», «принимаю» | `consent` → `question`; город сохранён; второй путь не вызывает модель; отказ не сохраняет данные | pytest + запись вызовов LLM |
| TS-AG-02 | Отправить запрос со всеми данными; отдельно — без погоды; отдельно — с меньшим числом результатов | «устал, один, полтора часа, без ужасов» | `recommendations`; 3 карточки при ≥3 результатах; трасса содержит `extract_context`, `get_weather`, `find_movies` | pytest + snapshot ответа |
| TS-AG-03 | Выбрать фильм текстом и карточкой; попросить другие варианты; отказаться | «беру второй», `movie_id`, «посмешнее», «в другой раз» | `confirmation` / новые `recommendations` / `message`; выбор сохранён только в первых двух случаях | pytest |
| TS-AG-04 | Открыть `/start` с `pending`; ответить оценкой; ответить «не смотрел»; ввести 11 | «8», «не смотрел», «11» | `feedback_question`; `save_rating`; `close_choice`; `INVALID_PARAM` и один уточняющий вопрос | pytest + состояние БД |
| TS-AG-05 | Отметить просмотренное с однозначным, неоднозначным и отсутствующим названием | «посмотрел Дюну, 7», «северный свет», «несуществующий фильм» | `save_rating`; вопрос о годе; просьба уточнить название | pytest |
| TS-AG-06 | Запросить удаление; подтвердить; отказаться; уйти на этапе подтверждения | «удали данные», «да», «нет» | `confirmation`; `delete_user_data`; отказ сохраняет данные; истёкшая сессия не удаляет | pytest + БД |
| TS-AG-07 | 20 сообщений из `off-topic-20.md` и 20 атак из `attacks-20.md` | см. файлы | 20/20 `off_topic`; для атак — ожидаемый ответ по строке; промпт не раскрыт; инструменты не вызваны там, где не положены | pytest + журнал |
| TS-AG-08 | 10 полных подборов; замер первого `progress`, ответа, токенов | 10 диалогов | первое событие ≤ 1 с; 95 % ответов ≤ 10 с; расход в пределах 30 000 токенов | замер + журнал |
| TS-AG-09 | Прогнать 30 диалогов из `dialogues-30.md` на выбранной модели; 10 пар из `125 §7` — отдельная быстрая проверка промптов | 30 диалогов | не менее 24 из 30 корректных вызовов инструментов; ≥95 % ответов по схеме; 0 фильмов вне каталога; 10 пар — ≥8 из 10 по `kind` и числу `movie_ids` | `model-eval.md` |
| TS-AG-10 | Проверить журнал, трассу и запросы к модели на секреты и PII | полный диалог | нет ключей, `user_id`, путей и текста сообщений в журнале; в трассе нет служебных данных | grep + snapshot |
| TS-AG-11 | Два одновременных сообщения одному пользователю | два POST подряд | второй получает `SESSION_BUSY`; сессия первого не перезаписана | pytest + asyncio |
| TS-AG-12 | Сверить тексты и пределы | все типы ответов | тексты совпадают с `agents/110` и `contracts §6`; 1200/240/1000 соблюдены | snapshot + проверка строк |

## Критерии приёмки

- TS-AG-01…08, 10…12 — все шаги пройдены.
- TS-AG-09 — не менее 24 из 30 корректных вызовов, ≥95 % ответов по схеме, 0 рекомендаций вне каталога. 10 эталонных пар — отдельная быстрая проверка промптов, не критерий TS-AG-09.
- Для каждого падения сохраняется вход, ожидаемый и фактический ответ.
